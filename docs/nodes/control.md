# 流程控制

## 开始 · Start

每个流程有一个开始节点，不能删除。配置输入声明、目标网址、页面加载超时、稳定等待、登录等待和最终 URL 校验。

配置目标网址意味着每次完整运行重新导航；“保持当前页面，不刷新”用于继续已准备好的页面状态。普通/强校验决定匹配方式，不决定是否刷新。详见 [运行与调试](../guide/execution.md)。

## 等待 · Wait

支持固定或随机等待，范围为 0–60000 毫秒的整数。随机模式设置最短和最长时长，两者都要有效且最短不大于最长。

当页面有明确完成状态时优先使用监控；等待节点不证明页面数据已经加载或业务已经完成。停止运行会取消等待。

## 循环 · Loop

1. 数组来源填写列表参数、检索输出或数据表行列表，例如 `{{记录列表}}`。
2. 配置当前项和索引变量，例如“当前项”“索引”。
3. 在内部画布添加每项处理步骤，从内部入口连接完整路径。
4. 内部普通节点末尾无需连回循环容器。
5. 容器外的完成出口连接循环之后的步骤，失败出口连接错误处理。

例如内部输入值使用 `{{当前项.编号}}`。最大遍历次数用于防止意外处理过多数据；内部页/项执行仍受全流程 1000 步的总预算约束。不要将循环输出理解为所有项结果的自动聚合。

旧版无 `body` 的外部回连循环保留兼容；新流程使用内部子流程形式。

## 分页 · Pagination

选择包含页码与上下页按钮的完整分页容器。两种模式：

| 模式 | 行为 |
| --- | --- |
| 到指定页 | 到达并校验目标页，执行一次内部流程；内部可为空 |
| 遍历每一页 | 从第 1 页开始，逐页执行非空内部流程，再翻到下一页 |

可用当前页变量，默认 `page`。正常结束条件可选到指定页后结束，或内部结果变量非空；最大页数是安全上限，到上限但仍有下一页会报告未完成，不能当作正常终止页。

翻页通过实际当前页确认。若网站数据在页码更新后延迟加载，应配置稳定等待或内部监控。内部节点不应私自改变当前页。

完整配置见 [分页与内部子流程](../pagination-and-subflows.md)。

## 失败分支

普通节点 `failure` 可以连接到输出、截图或其他处理步骤。失败分支处理完毕后，整个执行可能成功结束；业务目标是否达成需要用输出节点业务标记表达。

失败连线不是自动重试配置。对可能已经提交的操作，应先确认结果，避免盲目循环再次提交。

## 调用流程 · Action（兼容）

已有 Action 数据与 MCP 兼容接口仍保留，`action` 节点通过 `actionId` 调用已保存 Action。当前新增菜单与保存界面不提供创建新 Action 的入口。

新用户优先使用工作流与容器内部子流程，不要按历史文档寻找已移除的“保存 Action”按钮。

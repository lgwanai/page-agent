# 分页与内部子流程

当前操作已按扩展 0.10.66 / MCP 0.10.17 核对。

## 界面配置

1. 在开始节点或其他节点的右侧连接点添加“分页”。
2. 点击“选择分页容器”，选择包住页码和上下页按钮的完整 DOM，不能只选择某一个箭头。
3. 选择“到指定页”或“遍历每一页”。目标页支持 `{{page_number}}` 等输入变量。
   遍历时可设置“终止条件 → 到指定页码后结束”，填写 `10` 或 `{{last_page}}`，处理完该页后正常走完成出口。如果页面不足指定页数，遇到实际末页也正常结束。默认仍遍历到末页。
4. 点击容器内“添加内部节点”，配置每页需要运行的操作。选中内部节点后，点击下方“展开属性”编辑设置；内部节点右侧连接点继续添加分支或后续节点。
5. 完成出口连接分页之后的流程，失败出口连接恢复 / 通知流程。不配置失败出口时中止。

指定页模式到达并校验目标页后，执行一次内部流程（也可以留空）；遍历模式从第 1 页开始，每页执行内部流程，再翻到下一页。当前页变量默认 `page`，可在内部节点中使用 `{{page}}`。运行后还原外层同名变量，支持嵌套。

循环同样有内部画布：每个数组项执行一次内部流程，提供当前项和索引变量，内部末尾无需回连；旧版没有 `body` 的循环仍使用原来的外部回连逻辑。

## 识别和安全校验

- 当前页通过容器数据属性、选中状态、ARIA 或“当前 / 总页数”文本读取；不根据点击事件是否发送判定成功。
- 可见目标数字按钮优先；目标页被省略时使用上下页按钮。
- 图标方向通过按钮及其后代的 class、title、ARIA、图片名称等信息识别；一对无标签箭头可按排列推测方向，但实际翻页必须通过页码验证。
- 若实际方向错误，先尝试数字按钮或另一个箭头恢复原页，并记录实际方向；恢复失败则停止，不继续盲点。
- 末页需通过总页数或下一页按钮禁用状态确认。无法确认不会假装全部完成。
- 最大页数和导航操作数、每次翻页超时、翻页后稳定等待均可配置。达到上限仍有后续页视为未完成。
- 内部节点不得私自改变当前页；每页子流程执行后会重新检查。全流程最多 1000 个节点执行步，子流程最多嵌套 8 层。
- 子流程可能产生真实业务影响，重跑前应查看当前页与节点日志。站点在分页操作之后延迟加载数据时，应配置适当稳定等待或内部等待节点。

分页不调用 AI。Canvas、无当前页状态的自绘控件、极特殊分页结构不保证可识别，需根据诊断重新选容器或调整流程。

## JSON 与 MCP

工作流文件保持 `schemaVersion: 1`，新增 `pagination` 类型及可选内部 `body`；旧版插件不认识新节点，需要升级后导入。`body` 包含局部 `nodes`、`edges`、可选 `entryNodeId`，ID 和名称在整个工作流中唯一，连线不能跨子流程边界。内部入口是编辑器虚拟节点，不写入 JSON。

```json
{
  "id": "pages",
  "kind": "pagination",
  "name": "逐页处理",
  "target": {
    "name": "分页控件",
    "selector": ".pagination",
    "frameId": 0,
    "tagName": "div",
    "label": "分页"
  },
  "mode": "all",
  "page": "{{page_number}}",
  "pageVariable": "page",
  "stopAtPage": "10",
  "maxPages": 100,
  "timeoutMs": 5000,
  "settleMs": 300,
  "body": {
    "entryNodeId": "wait_each_page",
    "nodes": [
      { "id": "wait_each_page", "kind": "wait", "name": "每页等待", "durationMs": 500 }
    ],
    "edges": []
  }
}
```

分页与新循环外部端口是 `done`、`failure`；内部普通节点仍用 `success`、`failure`。内部循环 / 分页可以继续嵌套。MCP 工具 `get_page_workflow_toolkit` 提供新模板。

使用 `edit_page_workflow` 创建内部节点时，`add_node` 可携带 `parentNodeId` 指定容器；`update_node`、`remove_node` 支持内部节点 ID；`connect` 按节点所在作用域连接；`disconnect` 支持内部连线 ID。所有修改仍需对应工作流 key 和最新 `expectedUpdatedAt`。也可直接更新容器完整的 `body`。

`debug_page_node` 调试新循环 / 分页容器时会执行内部流程，不只是解析输入；不要把调试当作只读校验。只检查结构请调用 `validate_page_workflow`。

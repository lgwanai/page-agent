二、完整解压到固定目录

  1. Windows：右键压缩包，选择“全部解压缩”或使用企业认可的解压软件。Mac：双击 ZIP，等待解压结束。
  2. 将整个文件夹放到固定且有写入权限的位置，例如 Windows 的个人文档目录、Mac 的“文稿”目录。目录名称支持中文和空格。
  3. 确认能在同一目录看到下列文件和文件夹。Mac 包的最外层还有一个带版本号的文件夹，请进入该文件夹。

三、双击生成本机 MCP 配置

Windows

  1. 双击解压目录中的 Setup.cmd。
  2. 等待窗口提示配置已生成。成功时，目录中会出现 page-agent-mcp.json。
  3. 如果提示已复制到剪贴板，可直接用于下一步；按提示关闭窗口即可。

Mac

  1. 双击解压目录中的 Setup.command，系统会打开终端窗口。
  2. 等待提示配置已生成。成功时，同目录会出现 page-agent-mcp.json，配置也会尝试复制到剪贴板。
  3. 按窗口提示回车关闭。后续运行 MCP 不需要一直保持这个设置窗口打开。

成功标志：看到 Page Agent MCP configuration created，且同目录出现 JSON 文件。剪贴板复制失败不代表配置生成失败，仍可用文件导入，或用文本编辑器打开文件并复制全部内容。

真实路径配置：插件不提供占位目录或构建电脑的配置。Setup 还会同步写入 extension/mcp-local-config.json。运行 Setup 后重新加载插件，再打开 MCP 配置页，插件会读取这台电脑的真实路径。没有获取到有效配置时明确显示“尚未配置”，不显示配置 JSON，复制按钮不可用。不要复制说明中的目录示例作为配置。

如果已经有本机可用的 page-agent-mcp.json，可在插件 MCP 设置里点击导入本机 MCP 配置选择该文件，不需要再手动填写路径。v0.10.40 起，Setup 生成的配置优先于旧保存值和旧服务路径；明确导入或保存的配置会保留，切换到具有不同 Setup 路径的新包后会采用新包配置。服务报告的运行路径单独展示，不会覆盖本机配置。导入文件不会替您修改 Agent 客户端配置，仍需按第五节导入客户端。

升级用户：为什么运行了新 Setup，仍看到旧版本目录？

Setup 生成文件、Chrome 加载的扩展目录、Agent 客户端保存的配置、后台共享桥接是四个不同环节。Setup 只更新所在包的文件，不会自动切换 Chrome 目录、修改其他客户端或终止旧服务。v0.10.40 已修复旧服务覆盖新路径的问题；当服务与配置路径不同，MCP 面板会明确提示，并保留下方新配置 JSON。

  1. 先在原插件导出重要工作流备份；不要直接卸载原扩展，卸载会清除其本地数据。不同解压路径可能对应不同扩展 ID，工作流不会自动迁移到新扩展。
  2. 运行新包目录内的 Setup。窗口会列出包版本、MCP 可执行文件、服务脚本和 Chrome 扩展目录。核对生成的 JSON 是否属于本次解压位置，而不是只看剪贴板或旧客户端界面。
  3. 在 Chrome 扩展“详细信息”中核对加载目录。原扩展的重新加载不会切换目录。如需加载新包，请选择新包的 extension 目录，暂时禁用旧扩展避免操作错误实例，并核对侧栏版本为 0.10.51。需要时导入已备份的工作流，使用新实例的运行 Prompt。
  4. 将新包生成的 JSON 重新导入每个 MCP 客户端，保存并重连。只有插件内导入配置，不等于客户端已切换。
  5. 如果 MCP 面板仍提示当前服务是旧路径，说明旧共享桥接仍驻留。先确认没有工作流运行，再由管理员按面板显示的脚本完整路径识别并停止旧 Page Agent 桥接，然后重连客户端。不要结束所有 Node 进程；插件不会自行抢占或中断其他客户端。
路径核对：Setup 生成的 command 必须指向本次解压目录内的 runtime/node.exe 或 runtime/node，args[0] 必须指向同一目录内的 mcp-server/dist/index.js。不要复制其他版本的 JSON，也不要把旧包路径手动拼进新配置。插件的“当前服务脚本”是运行状态，下面可复制的 JSON 是准备使用的配置；两者不一致时，新 JSON 不会被旧服务覆盖。插件未获取本机配置时显示“尚未配置”，不显示占位目录。

本次 v0.10.51 交付的路径规则：压缩包不携带构建电脑生成的配置文件；Setup 依据自身所在的真实目录重新生成两个 JSON 文件，不会沿用系统 Node 或旧包的可执行文件路径。重新运行 Setup 会更新本包配置及配置修订标识；重新加载本包插件后会读取新配置，而不是继续使用上次保存的旧路径。不能在打包时预填客户未来的解压位置，必须在客户电脑运行本包 Setup 后才能得到该电脑的实际绝对路径。

目录名中含旧版本号本身不代表程序仍是旧版：如果您是在原目录覆盖更新，应同时核对实际加载版本、Setup 输出与客户端路径。未升级的旧扩展不会因运行新 Setup 自动获得 v0.10.40 的修复。

交付包尚未整体签名或公证。如系统、杀毒软件或企业策略阻止运行，请联系 IT 管理员或交付人员审核。不要关闭防火墙、安全防护，也不要执行网上提供的绕过安全检查命令。一般不需要管理员权限。

四、首次加载 Chrome 插件

  1. 打开 Chrome，在地址栏输入 chrome://extensions。
  2. 开启扩展管理页右上角的开发者模式。如企业不允许开启，请联系管理员按企业扩展策略部署。
  3. 点击加载已解压的扩展程序，选择解压目录里面的 extension 文件夹。不要选择 ZIP、整个交付目录或 mcp-server。
  4. 确认扩展列表出现“Page Agent”，并保持启用。可在 Chrome 扩展菜单将其固定，点击图标打开侧栏。
  5. 确认侧栏显示的实际加载版本：Windows 和 Mac 均为 0.10.51。如尚未连接 MCP，此时显示未连接是正常的，请继续下一节。

首次运行网页工作流前，打开目标业务页面并完成登录。更新或首次加载插件后，建议刷新目标业务页面，让新的页面脚本生效。无痕窗口、Chrome 内部页面、应用商店等受限页面可能不可操作；请先在普通窗口的 HTTP/HTTPS 网页上验证。

五、把配置导入 MCP 客户端

MCP 客户端是您使用的 Agent/AI 工具。不同客户端的菜单名称可能不同，请进入它的 MCP / 工具 / 连接器 / 服务配置设置区域，选择以下一种方式。这里不需要 HTTP 服务地址，也不需要填写 WebSocket 地址。

客户端提供的入口操作方法
“导入 JSON / 导入配置文件”选择当前电脑刚生成的 page-agent-mcp.json。
完整 JSON 配置编辑器若尚无其他服务，粘贴生成的全部 JSON；若已有其他服务，只将生成配置中 mcpServers 下的 page-agent 条目合并进去，保留其他条目。不要把两个顶层 JSON 对象直接拼接。不熟悉合并时请联系 IT 支持。
单个服务配置表单选择本地命令 / stdio 类型。将生成文件中的 command、args、env 分别复制到对应字段，不需要自行寻找或改写路径。若客户端要求的格式不同，请由支持人员按其格式导入。
  1. 完成导入后保存，并启用或连接 page-agent 服务。
  2. 如客户端未自动重启服务，请在客户端重新连接；必要时退出并重新打开客户端。
  3. 根据客户端要求，为当前对话启用 Page Agent 工具。某些客户端需要新建对话后才能看到新增工具。

六、验证连接，再运行工作流

  1. 保持 Chrome、Page Agent 插件和 MCP 客户端开启。插件侧栏的 MCP 状态应显示已连接本机服务；若状态未更新，可打开 MCP 设置刷新状态或重试连接。
  2. 在已启用 Page Agent 的 Agent 对话中输入下面的只读验证请求。它只检查连接，不运行业务工作流。
请使用 Page Agent MCP，调用 list_page_agent_instances 列出插件实例，
找到与插件侧栏实例 ID 一致的实例，再调用 page_agent_status 检查该实例状态。
这次只验证连接，不执行工作流，也不要提交、导出或修改业务数据。

验收成功：客户端能看到 Page Agent 工具，实例列表中出现当前 Chrome 插件的实例 ID，状态检查正常；若有多个 Chrome 配置文件或实例，应按插件侧栏的实例 ID 确认目标，而不是只看网页标题。

需要执行工作流时，先创建或导入并保存工作流，再使用列表中的复制运行 Prompt交给已连接 MCP 的可信 Agent。执行需要插件实例 ID、工作流 ID、该工作流的 key，以及工作流声明的输入参数。空列表并不代表连接失败。

七、页面操作、事件录制与工作流管理

1. 自动确认页面 alert

工作流运行和单节点调试期间，Page Agent 会自动确认目标标签页的原生 JavaScript alert，避免提示框阻断后续流程。无需在画布中单独添加确认节点。执行结束或报错后，会释放本次使用的调试连接；不在运行期间全局处理所有网页。

升级权限提示：v0.10.38 新增 Chrome debugger 调试权限，用于处理原生 alert。重新加载扩展后，如 Chrome 要求确认新增权限，请按企业审批要求授权并确保扩展启用。运行时可能显示浏览器正在被调试的提示。未授权或被企业策略禁止时，自动处理能力不可用。

不会自动确认的内容：confirm 确认/取消框、prompt 输入框、离开页面的 beforeunload 提示，以及网站自己绘制的弹窗。自绘弹窗仍需通过 Selector 等节点操作。若目标标签页被其他调试器占用，会明确报错，不会抢占已有调试连接；请在确认安全后释放占用再重试。

2. 录制与回放网页拖拽

  1. 创建工作流时选择录制，等待网页出现录制状态条。
  2. 将鼠标放在浮层、面板等组件允许拖动的把手或标题区域，按下左键，拖动到目标位置后松开。例如，先把遮挡操作按钮的浮层移到一边，再点击露出的按钮。
  3. 继续其他操作，最后点击停止。画布会生成“拖拽移动”操作节点，保存起点、位移和轨迹；正常情况下不会再生成一次尾随点击。
  4. 在画布中检查节点及连接顺序，先单步测试拖拽，再测试后续点击，确认成功后保存工作流。旧录制中缺失的拖拽动作不会自动补齐，需要重新录制或手动配置。

拖拽节点的参数里，dx 为水平位移、dy 为垂直位移，单位为像素；正数向右/下，负数向左/上，durationMs 为持续时间。通常使用录制自动生成的值即可，不必手工填写轨迹。回放会检查是否发生元素位置、结构或拖放内容变化；仅发出事件但没有可检测结果时，会判为失败并按失败分支处理。

范围与限制：这是网页 DOM 拖拽，不是操作系统窗口或桌面文件拖放。不同网页控件对模拟事件的支持不同，要求可信用户输入的特殊控件可能不接受回放。请在目标页面验证，不要将录制成功等同于回放一定成功。后续元素仍被遮挡时，请检查拖动把手、方向、距离和运行前的页面布局。

3. 开始节点保持当前页面，不刷新

适用于必须先人工点击多级菜单、打开弹层、填写表单或进入 iframe 内部界面的页面，避免工作流运行时重新打开 URL 导致界面状态丢失。

  1. 在浏览器中手动进入需要继续操作的界面，保持这个业务标签页为当前活动标签页。
  2. 进入画布编辑，选中开始节点，勾选“保持当前页面，不跳转、不刷新”。
  3. 检查后续 Selector 是否对应此刻页面中的元素，保存工作流后运行。

开启后，不会由开始节点导航或刷新页面；已有目标 URL 暂不使用，其目标 URL 校验和等待登录跳转逻辑也不执行。当前页面仍须是可操作的 HTTP/HTTPS 网页，页面加载与稳定等待仍可能发生。此设置不能阻止网站自身刷新，也不保证页面长期不变化。

此选项默认关闭，兼容原有工作流。关闭且填写目标 URL 时，仍按原逻辑重新打开该地址；要从固定入口重新开始，请关闭此选项。无需导航但保留人工状态的场景，应明确勾选，不要只依赖 URL 相同。

4. 新增事件录制（v0.10.42）

  1. 升级后重新加载插件，并刷新目标业务网页。在工作流列表点击创建工作流 → 录制，等待悬浮录制状态条出现。
  2. 按实际业务顺序操作。例如：点击输入框、输入内容、点击下一个字段触发失焦保存；或移入菜单、选择菜单项。支持输入法、粘贴与剪切后最终内容的采集，不需要手工添加每个底层事件。
  3. 完成后点击悬浮条上的停止，检查生成的画布。选中 Selector 节点即可查看和修改操作；可用操作根据目标 DOM 类型显示。
  4. 先单步运行，再从开始节点验证整个流程，检查网页实际结果和节点日志，最后保存或更新工作流。历史录制不会自动补齐新事件，需要重新录制或手动补充。
交互类型新增或增强的记录与回放使用要点
进入与离开焦点focus / blur、focusin / focusout同次事件去重；v0.10.47 起仅在焦点引起内容、校验或控件状态变化时保留步骤，不为纯焦点样式生成节点。输入可保留焦点至实际离开；有意义的失焦节点可记录下一个焦点目标 Selector。
鼠标或指针进入、移出鼠标悬停、鼠标移出仅在触发菜单显隐、内容或控件状态变化时保留；纯鼠标经过不产生节点。鼠标/指针边界去重，控件内部子元素之间移动不会重复生成移入/移出节点，不逐帧记录 mousemove。
变更与表单重置独立 change、表单 reset常规输入、下拉、勾选仍记录为语义操作；独立 change 只触发变更事件，不代替填写值。由已录制重置按钮点击引起的 reset 不再重复记录。
键盘操作Tab、Home、End、方向键、PageUp/PageDown、F1–F12，以及 Ctrl/Alt/Shift/Command 组合键节点“按键”中配置 key，空格使用 Space，回车使用 Enter；修饰键通过复选框配置。录制保留可用的 code；Space 激活产生的尾随点击、Enter 隐式提交会去重。
输入法、粘贴与剪切采集输入法结束后的最终内容，及粘贴、剪切、拖放后字段的最终值不把输入法中间文本或选字回车当成独立提交，不直接读取剪贴板。密码字段使用变量占位，不把明文密码录入工作流；普通字段中的敏感内容仍需人工检查和脱敏。

如需手动编辑焦点顺序，输入节点可勾选“输入后保留焦点，交给后续焦点节点处理”，随后连接“离开焦点（focusout）”等节点。下一个焦点目标 Selector 应唯一且可用；不要将同一次切换再配置成重复操作。

支持边界：录制把网页交互转换为可编辑操作，不是监听并逐一重放所有 DOM 原始事件。浏览器地址栏、操作系统快捷键、剪贴板特权操作、要求可信用户事件的控件，不保证能通过合成事件回放。组合键记录成功不等于浏览器或系统会执行对应功能；请以目标页面实测为准。

5. 工作流重命名（v0.10.42）

  1. 在工作流列表找到需要修改的工作流，点击该项的更多操作 → 重命名；也可打开已保存工作流的编辑页，点击标题旁的铅笔按钮。
  2. 输入 1–120 个字符的名称，点击确认重命名。首尾空白自动去除，不接受空名称或换行。取消或按 Escape 不会保存更改。
  3. 返回列表或重新打开编辑页核对新名称。重命名只修改工作流名称，不改变工作流 ID、访问 key、节点配置或输入参数，原有按 ID/key 的 MCP 调用仍可使用。

编辑页中尚未保存的节点改动不会因重命名丢失，但重命名不等于保存画布：节点改动仍需点击“更新工作流”。如果其他客户端已修改工作流，会提示冲突而不是覆盖；请保留自己的改动，核对最新工作流后再操作。重命名的是整个工作流，不会更改节点 name 或变量引用。

6. 手动输入参数、区间日历与 Output（v0.10.43–0.10.46）

开始节点可声明文本、数字、列表、对象、对象列表。列表运行和画布运行会弹出匹配类型的输入表单，对象及列表可分层编辑，也可粘贴 JSON；本机记住上次手动填写内容，方便测试。MCP 只使用本次 data，绝不使用手动填写历史补齐参数。必填参数未提供时，调用会明确报错。

例如，开始节点声明必填文本参数 task_name、start_time、end_time，输入节点填写 {{task_name}}，区间日历的目标日期和结束日期分别填写 {{start_time}}、{{end_time}}。以下仅为运行时的 data，不是 MCP 服务配置，也不能当作本机文件路径：

{
  "task_name": "测试表单导出",
  "start_time": "2026-10-01",
  "end_time": "2026-10-11"
}

区间日历在选择结束日期前切换到结束输入框，并最终核验两个框的实际值；开始被覆盖、结束为空或日期不一致会失败。v0.10.45 补齐侧栏持有窗口焦点时 Chrome 缺失的 focus/focusin 等事件，不再只根据 activeElement 判断控件已切换。更新后请重新加载插件、刷新业务页。

在画布或出口菜单添加 Output，选择输出来源：文本（可拼接变量）、变量（保留对象/数组等原始类型）、前序节点（可指定字段路径），或 DOM（使用 Selector 选择元素，读取文本、当前 value、指定属性，也可返回匹配列表）。缺失变量、未执行的前序节点、缺失 DOM/属性会报错；不能读取密码或隐藏输入。

Query 可设置“没有匹配项时 → 走失败出口”，连接 Output 返回固定文字。例如第一列无同名任务返回“未找到导出任务”；第三列未包含“取数完成”返回“未成功”；只有满足条件才连接下载操作。Query 的其他错误也走失败出口，应结合日志区分“无匹配”和页面异常。

{
  "ok": true,
  "businessOk": false,
  "output": "未找到导出任务",
  "outputs": { "未找到任务结果": "未找到导出任务" }
}

ok 表示执行路径正常结束或错误已被分支处理；businessOk 是 Output 业务结果标记，二者不能混用。output 为最后一次输出，outputs 按节点名称汇总；循环内部输出也会返回，每次运行独立收集。Output 可以连接后续，不连接即结束当前路径；它不是强制退出所有循环的指令。“已触发下载”仅表示点击执行，不等于文件已完整落盘。

工作流与密钥不随免安装包分发。客户需自行创建或导入工作流；当前电脑浏览器中已保存的任务、实例 ID、访问 key 和手动输入记录不包含在本包内。更新工作流配置不等于修改插件版本，重新打开已保存画布才能读取其他客户端的最新修改。

7. Selector 与动态页面定位修复（v0.10.47–0.10.49）

手动选取与录制采用同一套控件识别。点击按钮内的文字或图标时会识别对应按钮；选取时重新检查点击位置，避免保存已经移动或失效的高亮目标。不同页面状态下生成的 CSS 文本不一定完全相同，应检查目标是否唯一、可见且为预期控件，而不是只比较路径长短。

SPA 动态地址：手动选取现在保留选取瞬间的实时页面地址，不再被浏览器消息中的旧地址覆盖。对于每次进入页面重新生成的 processId，新捕获会自动保存页面查询参数范围，排除此运行时参数，仍核对站点、页面路径及其余业务参数（如活动 ID）。不能理解为“忽略全部查询参数”或允许跨活动、跨网站操作。

旧工作流需要检查：旧节点未声明新的参数范围时仍按完整 URL 精确匹配，不会擅自改变旧任务的定位限制。升级后请在真实目标界面重新选取受影响节点，点击更新工作流，重新打开确认，再先单步、后整段验证。不能只运行 Setup：Setup 仅生成本机 MCP 文件路径，不修正网页 Selector 或旧节点地址。

新标签页和 iframe：执行器跟随本次流程操作新开的匹配目标标签页，并等待读取其最终 SPA 地址；不会因为标题相同就操作任意已有标签页。iframe 需要在所属文档中定位，不能把每次变化的 frame 编号当作永久身份。出现多个匹配文档或多个同名控件时会停止，而不是随意选择第一个。

页面脚本连接：本包包含固定路径、无动态导入的单文件 content-script.js，降低扩展重载及构建更新后的脚本加载失败风险；握手会核对页面脚本版本。请完整加载本包的 extension 目录，不要单独替换某个 JS 文件，也不要在工作流运行中更新文件。

录制去噪：无实际效果的鼠标经过、移出及焦点样式变化不再直接生成节点。触发菜单显隐、内容或控件状态变化的事件仍可保留；点击、输入、按键和拖拽不会仅因页面变化很少就被删除。旧画布上的多余节点不会被自动删除，需编辑后保存。

错误或现象如何处理
FRAME_DOCUMENT_MISMATCH页面地址范围不匹配，尚未进行 CSS 定位。比较日志中的目标地址与当前 frame 地址；在正确界面重新选取并保存，动态参数应由新捕获正确处理。
CONTENT_SCRIPT_UNAVAILABLE检查错误详情中的脚本注入/握手原因、实际插件版本及加载目录；重新加载完整插件，必要时刷新业务页。不是所有此类错误都代表 CSS 写错。
SELECTOR_NOT_FOUND文档可用但未找到目标。检查是否已打开菜单、抽屉或弹层，及节点的控件身份、页面状态与前置操作。
验收以网页实际结果为准。例如点击“去选择”后应出现“选择品牌/类目”抽屉；不能仅凭日志写着“已捕获 click”就认为业务操作成功。运行结果中的 runId 可用于支持排查；涉及提交、下载等副作用时不要盲目重跑。

8. 日历时分秒选择与活动起止参数（v0.10.51）

带小时、分钟、秒的活动时间，请使用日历节点的区间模式，不要拆成两个普通输入节点。v0.10.51 增加独立的 Fusion Next 日期时间区间适配：点击日期格、分别点击两端的时/分/秒选项，再点击日历弹层内部的“确定”，最后同时核验主表单起止实际值。仅日期格式 YYYY-MM-DD 仍走原有日期选择路径，旧工作流不需要为了本次升级修改格式。

支持范围：新增时分秒能力当前针对 Fusion Next 日期时间区间控件，不代表所有网站的时间控件都已适配。控件不支持、归属不唯一、日期/时间被禁用、起止值错误或被回滚时明确失败，不会忽略时间、移除禁用状态或只凭点击事件报成功。

配置步骤

  1. 在开始节点添加两个文本、必须提供参数：activity_start_time（活动开始时间）、activity_end_time（活动结束时间）。值使用 YYYY-MM-DD HH:mm:ss，例如 2026-11-01 10:11:12。这是页面本地时间，不做时区换算。
  2. 类目确认并核验主表单后，等待抽屉关闭动画结束，再用 Selector 点击活动时间的起始输入框，打开日历。若省略等待，仍在消退的遮罩可能阻挡点击；不要改成强制点击。
  3. 添加并命名日历节点，例如设置活动时间。选择包含日期、时间与确定按钮的完整弹层，不能只选择输入框或某一列时间。选择方式设为选择开始和结束日期。
  4. “目标日期 / 开始时间”填写 {{activity_start_time}}；“结束日期 / 时间”填写 {{activity_end_time}}。保存或更新工作流。
  5. 运行会显式切换开始、结束日期，选择年月日；再打开时间面板并分别点击两端时、分、秒。提交日历之前核验两端草稿，提交日历之后核验主表单完整日期时间并稳定至少 300 毫秒。开始被结束覆盖、结束为空、秒不一致、弹层未关闭等均失败。
  6. 建议后接两个 Watch：对主表单起始/结束输入框读取DOM 值，完全等于 {{设置活动时间.output.0}} 和 {{设置活动时间.output.1}}。最后连接 Output，返回 Watch 读取的实际值。请替换为实际节点名称和页面 Selector。

下面是带类目选择的工作流运行 data 示例，不是 MCP 服务配置，也不是本机文件路径；并不表示交付包已包含这条业务工作流：

八、表格填充节点（v0.10.41 多结构支持）

将 Excel 按表头整理的数据批量填入网页的可编辑表格。节点先用您指定的一个或多个 key 列找到对应行，再按同名表头填入其他列；不需要为每一行单独录制点击和输入，也不需要配置 AI 供应商。

输入是对象数组，不是 Excel 文件本身。请由可信 Agent 或企业认可的工具将 Excel 转换为下方的 JSON 数据，每一行对应一个对象，字段名称与网页表头一致。此节点不直接读取或上传 .xlsx。编号、SKU、带前导零的编码请保留为文本，例如 "00123"。

1. 配置开始节点与表格填充节点

  1. 打开并登录业务页面，确保要填写的表格已显示。如需保留人工进入的界面，可在开始节点勾选“保持当前页面，不跳转、不刷新”。
  2. 在开始节点的 MCP JSON 输入中添加参数：名称填 data，数据类型选择对象列表（即对象数组），建议勾选必须提供。参数名称区分大小写，后续引用必须一致。
  3. 从开始节点或上游节点的连接点添加表格填充节点，给它命名，例如 库存填充。
  4. 点击在网页选择可编辑表格，像使用 Selector 一样选择同时包含表头和数据行的完整外层容器，确认“表格 Selector”只匹配一个容器。支持 table、ARIA 表格、ul/li、div，以及 table 表头配 div 行、分离表头/表体 table。不要只选一个输入框、表头或表体，也不要把多个独立表格一起圈入。
  5. 填充数据填写 {{data}}。也可引用已有 DataTable 节点的 {{数据表.rows}}，其中“数据表”应替换为您的节点名称。这里新增的是表格填充能力，不表示 DataTable 提取节点也能读取任意 div/ul 表格。
  6. 在匹配 key 列（组合匹配）填写网页表头的列名。例如先填 SKU，再点击＋ 添加 key 列填 仓库。多个 key 必须同时相等才匹配；key 列只定位行，不会被改写。不要把希望修改的列设为 key。
  7. 默认留空高级结构，先让节点自动识别。如果报“多个可能的表头/数据行区域”或无法识别，先缩小外层容器，再按下文配置高级 Selector。先用一两行测试，查看节点日志及网页实际结果，确认后保存或更新工作流。此节点不会自动点击页面上的“保存”“提交”等业务按钮。

2. data 参数示例：SKU + 仓库组合匹配

假设网页表头是 SKU、仓库、数量、状态、标签、启用，其中 SKU 与仓库共同确定一行，其他列按实际控件填写。以下为工作流输入参数对象，不是 MCP 客户端的服务配置，也不是完整工具调用参数：

{
  "data": [
    {
      "SKU": "A001",
      "仓库": "上海",
      "数量": 12,
      "状态": "启用",
      "标签": ["红色", "大号"],
      "启用": true
    },
    {
      "SKU": "A001",
      "仓库": "北京",
      "数量": 8,
      "状态": "停用",
      "标签": ["蓝色"],
      "启用": false
    }
  ]
}

手动运行画布：弹出参数输入窗口时，将上例 data 对应的数组（从 [ 到 ]）填入 data 字段，不要重复包一层 data。画布记住的手动输入仅供下次手动运行，不会替代或覆盖 MCP 调用传入的参数。

通过 MCP 运行：在工作流列表点击“复制运行 Prompt”，保留其中的插件实例 ID、工作流 ID 和 key，并附上上例输入参数。要求 Agent 使用这些参数执行该工作流；请只把包含 key 和业务数据的 Prompt 交给可信的 Agent，不要公开分享。每次 MCP 调用都需传本次 data。

3. 不同控件应该传什么值

网页单元格建议数据格式处理方式
输入框、文本域、可编辑文本"备注内容"、12按类型输入；普通文本框不接受数组或对象，数字框拒绝非数字。
单选下拉框、单选按钮组"启用"优先匹配选项 value，其次匹配可见文字；需唯一且可用，不能传多个选项。
多选下拉框、复选框组["红色", "大号"]逐项精确匹配。推荐数组，不依赖逗号分隔。
单个复选框true 或 false分别表示选中或取消选中，不要传选项数组。
只读、禁用、普通展示列可省略对应字段自动跳过并记录原因；data 中没有的列不会填写，网页中没有的字段会跳过。

数据字段按表头名称而非列的位置匹配，因此 Excel 与网页列顺序可以不同。省略字段表示不处理；空字符串或 null 会对可编辑文本执行清空，并非“跳过”。请勿将缺失的 Excel 单元格统一替换为空值后直接批量运行。

4. ul/li、div 和表头/表体分离：应该选哪里？

以下三个片段是用于说明页面结构的 HTML 示例，不需要粘贴进插件，也不需要修改客户网站。实际使用时选择网站中对应的完整容器，字段名与网页表头保持一致。下面的 #stock-grid 只是示例元素 ID，不是 MCP 文件路径，不能直接套用到其他页面。

三个示例统一使用：key 列 SKU + 仓库，填充数据 {{data}}，以及以下工作流输入：

{
  "data": [
    { "SKU": "A001", "仓库": "上海", "数量": 12 }
  ]
}

A. ul/li：选择同时包住表头 li 和数据 li 的整个 ul。每行内部的 span/div 才是单元格，不要把单选/下拉列表里的 li 误当成数据行。

<ul id="stock-grid">
  <li class="grid-head">
    <span>SKU</span><span>仓库</span><span>数量</span>
  </li>
  <li class="grid-row">
    <span>A001</span><span>上海</span><span><input value="0"></span>
  </li>
</ul>

B. 纯 div：选择包含 grid-head 和 grid-body 的最外层 div。没有 table 标签、也没有 ARIA 角色时，节点会结合表头字段和重复行结构识别；仅有几块 div 并不保证足以判断成表格。

<div id="stock-grid">
  <div class="grid-head">
    <div class="cell">SKU</div><div class="cell">仓库</div><div class="cell">数量</div>
  </div>
  <div class="grid-body">
    <div class="grid-row">
      <div class="cell">A001</div><div class="cell">上海</div>
      <div class="cell"><input value="0"></div>
    </div>
  </div>
</div>

C. table 做表头、div 做数据行：必须选择二者的共同外层容器，不能只选上面的 table；否则选区内根本没有可填写的数据行。表头 table 与数据 table 分离时同理，应选择共同容器，而不是任意拼接两个独立表格。

<div id="stock-grid">
  <div class="grid-head">
    <table><thead><tr><th>SKU</th><th>仓库</th><th>数量</th></tr></thead></table>
  </div>
  <div class="grid-body">
    <div class="grid-row">
      <div class="cell">A001</div><div class="cell">上海</div>
      <div class="cell"><input value="0"></div>
    </div>
  </div>
</div>

5. 高级 Selector：分别指定表头、数据行和单元格

在表格填充节点展开“高级结构配置（自动识别不明确时使用）”。三个字段都可留空，留空项继续自动识别；如果出现副本、复杂包装层或多个候选区域，可指定其中一项或全部三项。不需要改动 data 或 key 的配置。

界面字段相对哪个范围应该匹配什么
表头单元格 Selector上方“表格 Selector”选中的完整容器每一列的表头单元格，如 .grid-head thead th；不是整个 thead 或标题栏。
数据行 Selector同一个完整容器每一条真实数据行；排除表头、汇总行、分页条及重复展示副本。
行内单元格 Selector每一个已匹配的数据行包含展示文字/输入框的单元格外层，如 :scope > .cell；不要只选 input、select。

上面三个 HTML 示例对应的完整配置如下。前三行可直接与对应示例核对；实际网站必须替换为实际类名、ID 和结构：

结构表格 Selector表头单元格数据行行内单元格
ul/li（A）#stock-grid:scope > .grid-head > span:scope > .grid-row:scope > span
纯 div（B）#stock-grid.grid-head > .cell.grid-body > .grid-row:scope > .cell
table 表头 + div 行（C）#stock-grid.grid-head thead th.grid-body > .grid-row:scope > .cell
表头/表体两个 table二者的共同外层容器.grid-head thead th.grid-body tbody > tr:scope > td

:scope 表示当前范围，> 表示直接子元素。因此“行内单元格”填写 :scope > .cell 是每行直接包含的 cell，不是从整页查找所有 cell。这些字段只接受 CSS Selector，不接受 XPath。

如果由 Agent 通过 MCP 创建或修改节点，对应的节点属性片段如下。它是表格填充节点的配置片段，不是 MCP 服务连接 JSON，也不是完整工作流文件：

{
  "structure": {
    "headerSelector": ".grid-head thead th",
    "rowSelector": ".grid-body > .grid-row",
    "cellSelector": ":scope > .cell"
  }
}
  • 先确认每行选择出的单元格数量与表头列数一致，并按相同列顺序排列。支持明确的列标识自动映射，但不能依赖网页视觉位置推断任意错序。
  • 可见的固定列副本、两个同名表头或两个可能的数据区域会产生歧义。请缩小选区或用更精确的高级 Selector 排除副本；不要把所有候选行强行合并。
  • 多级合并表头优先保留自动识别；手动指定表头时应选出最终各列名称，避免将分组标题与子标题一起选中。合并数据单元格仍不支持自动填充。
  • 配置保存后可重新打开编辑，JSON 导入导出及 MCP 也会保留 structure。成功报告的 structure 包含识别布局、列名和已加载行数，可在节点日志中核对。

6. 分页、校验与失败处理

  • 只处理当前页面已加载的行：不会自动翻页或滚动加载虚拟表格。可把表格填充放进分页节点的内部子流程，并勾选跳过当前页面未匹配的数据行（分页场景）。该选项仅跳过本页找不到的输入行，不会跨页校验所有输入最终均已命中；请自行核对覆盖范围。
  • 写入前检查 key：data 缺少 key、组合 key 重复、网页同一 key 命中多行，或默认配置下找不到输入行时，会报错，避免填错行。不要依赖行号代替稳定的业务 key。
  • 填写后复核：每个单元格填写后检查实际值，最后再次检查已填值。如果页面脚本回退内容、选项不存在/不唯一或操作失败，节点会判定失败，可连接失败路径处理。
  • 失败不自动回滚：写入前的 key 检查不能预知所有控件问题。中途失败时，之前已填写的单元格可能保留；先检查页面与节点详情，不要不加核对地再次执行。详情中的 verification.actual 包含可用的部分填充明细。
  • 结果记录：成功日志包含匹配行数、已填单元格数、跳过单元格及未匹配数据行数。后续节点可通过 {{库存填充.filledCells}} 引用已填单元格数；请替换为实际节点名称。
  • 支持范围：支持已识别的 table、ARIA、ul/li、div 和表头/表体分离结构中的常见控件；特殊自定义下拉、弹窗编辑器、缺少可判断表头的页面以及合并数据单元格等仍不能保证适配。无法明确识别时停止或跳过并给出原因，需在目标业务页面实测。
  • 批量上限：每次 data 不超过 5000 行、合计 50000 个字段；当前网页表格不超过 5000 行、200 列。大数据请分批或按页处理。
不会自动提交业务表单，也不代表服务器已保存。但填写会触发网页的输入与变更事件，有自动保存逻辑的网站仍可能立刻写入业务系统。请先使用测试环境或测试记录，并遵守企业授权和数据安全政策。

九、常见问题与连接排查

双击后没有生成 page-agent-mcp.json

确认 ZIP 已完整解压、运行的是 Setup 文件、芯片版本选择正确，并保留 runtime 和 mcp-server。将整个目录移到个人可写目录后重试。若终端提示程序被阻止、权限不足或不兼容，请截图联系支持人员；不要先安装依赖或自行替换 Node。

客户端提示 “Connection closed / MCP error -32000 / 服务启动失败”

重新运行当前目录的 Setup，重新导入本次生成的配置，再重连客户端。检查目录是否在导入后被移动、重命名、删除或被安全软件隔离；确认导入的是当前电脑生成的文件，而不是他人的 JSON。仍失败时，请提供客户端的启动错误日志或 stderr，不要只截“Connection closed”这一行。

客户端能看到工具，但插件显示未连接，或列表中没有当前实例

确认 Chrome 中正确的 Page Agent 扩展已启用，且打开的是您要操作的 Chrome 实例/配置文件。MCP 客户端需要实际启用 page-agent 服务，仅运行 Setup 不会启动常驻服务。打开插件 MCP 设置刷新状态或重试连接。若仍离线，请让 IT 检查本机 127.0.0.1:17373 的占用与安全软件策略；不要开放外网端口或关闭防火墙。

工具不存在、没有连接器，或新对话看不到工具

确认当前客户端保存并启用了 page-agent，且该工具已向当前会话开放。按客户端要求重新连接或新建对话。插件里的“记住配置”不会替您修改 AI 客户端的 MCP 配置。

提示端口冲突、旧服务不支持多客户端或旧版桥接

多个 Agent 客户端可以共用一套本机共享桥接。升级时旧桥接进程可能仍在运行；请联系 IT 按本机端口和程序路径识别并停止旧 Page Agent 桥接，然后重新连接所有相关 MCP 客户端。不要结束所有 Node 进程，也不要反复修改固定桥接端口。

文件夹搬家、重命名或换了一台电脑

把完整目录放到新位置后，再次双击 Setup，重新导入新生成的配置并重连 MCP。新电脑必须使用匹配系统/芯片的交付包。配置包含本机绝对路径，不能跨电脑直接复用。若 extension 路径改变，也需重新加载相应的插件目录。

Chrome 提示找不到 manifest、插件没有更新，或网页 Selector 不能启动

加载目录必须是含 manifest.json 的 extension 文件夹。更新后在扩展管理页重新加载，并在侧栏核对实际版本，然后刷新目标业务网页。Selector 请用于普通 HTTP/HTTPS 页面。企业禁止开发者模式或网页访问权限时，联系管理员，不要尝试绕过。

运行工作流提示实例、工作流或 key 不匹配

按插件侧栏核对当前实例 ID，使用当前工作流的“复制运行 Prompt”重新复制调用信息。导入工作流到新电脑后，应使用新电脑插件中的调用信息，不要继续用旧机器的 key。多个客户端不能同时抢占同一实例执行流程；若提示忙，请等待当前任务结束。

业务网页未登录、节点找不到或运行超时

连接成功不等于业务流程一定成功。先检查目标页面是否正确、登录是否有效、节点对应元素是否可见。查看画布节点详情中的错误日志，确认是否已有业务操作发生。对于提交、发送、导出等动作，结果不明时不要反复重跑，应先检查业务系统或联系支持人员。

十、日常使用、更新与安全

  • 正常使用时无需反复执行 Setup。保持安装目录不变，由 MCP 客户端启动服务即可；浏览器和业务页面需要处于可访问状态。
  • 升级前导出重要工作流 JSON，并记录交付版本。不要删除旧插件来尝试升级，删除插件可能丢失其本地数据。新增加载的插件或不同 Chrome 配置文件不保证自动继承旧工作流；按交付人员指导更新，必要时导入工作流并重新获取调用信息。
  • 工作流导出文件不包含访问 key；请把 key 和包含 key 的运行 Prompt 当作密码，仅交给可信工具。排障截图和日志需先遮盖 key、登录凭证及敏感业务数据。
  • 免安装只表示运行环境已经随包提供，不代表所有业务均离线。访问业务网页、调用 AI、邮件发送等仍取决于网络、账号权限和节点配置；Agent 也可能读取工作流返回的内容，请遵守企业数据政策。
  • 当前包未整体签名/公证，不会自动注册开机启动或修改防火墙。企业限制场景请由管理员审核部署。

  1. 操作系统版本、芯片类型，以及下载的完整压缩包名称。
  2. 插件侧栏显示的实际版本，使用的 MCP 客户端名称及版本。

# 日历节点：日期时间区间（v0.10.51）

## 适用范围与兼容性

日历节点仍使用 `kind: "calendar"`、`date`、`endDate`、`mode`，不改变工作流 JSON 字段。

- `YYYY-MM-DD` 仍走原有日期选择逻辑，原有 Aurora、Ant/通用单日、区间和内嵌日历测试保持通过。
- 请求中含时间时进入独立适配器。目前支持带 `.next-range-picker-body-show-time` 的 Fusion Next 日期时间区间弹层。开始、结束必须都提供时间；不支持的控件明确失败，不会退化成仅设置日期。
- 格式为 `YYYY-MM-DD HH:mm:ss`，也接受 `T` 分隔和 `/` 日期分隔；分钟精度输入补零秒。值按页面本地墙上时间解释，不做时区转换，不接受 `Z` 或 UTC 偏移。
- 同时检查日期有效性、24 小时制时分秒范围、完整结束时间不得早于开始时间。

## 配置示例

Start 增加两个文本参数：`activity_start_time`、`activity_end_time`。传参示例：

```json
{
  "filter_category": "",
  "category_name": "家居饰品",
  "activity_start_time": "2026-10-17 09:10:11",
  "activity_end_time": "2026-11-17 18:20:21"
}
```

在类目确定、主表单类目核验成功后，点击主表单起始日期输入框，再连接日历节点：

```json
{
  "id": "activity_datetime",
  "kind": "calendar",
  "name": "设置活动时间",
  "mode": "range",
  "date": "{{activity_start_time}}",
  "endDate": "{{activity_end_time}}",
  "target": {
    "name": "活动日期时间弹层",
    "selector": ".next-overlay-wrapper.opened > .next-range-picker-body-show-time",
    "frameId": 0,
    "tagName": "div",
    "label": "活动日期时间弹层"
  }
}
```

实际工作流还应保留原页面的 `frameUrl`、`frameQueryKeys` 身份保护，不要在未检查页面时直接套用示例。日期范围和最短/最长活动时长由业务页面决定，本节点不移除禁用状态、不绕过校验。

## 操作与核验

1. 关联唯一打开的 Fusion Next 区间控件及其主表单两个输入框；存在多组打开控件或无法关联时停止，避免读取其他日期控件冒充成功。
2. 显式切换弹层内部开始/结束日期焦点，点击实际日期格；超出显示月份时点击月份图标并核验真实年月变化，异常时尝试恢复后失败，不继续猜测。
3. 点击日历内“选择时间”，分别点击开始和结束的小时、分钟、秒选项。每列校验实际选中项，不向输入框注入时间文本，也不调用网页组件内部方法。
4. 同时核验内部起止日期时间草稿，包含秒；不匹配不点击确定。
5. 仅点击日历弹层内部“确定”，不点击主业务表单提交。要求弹层关闭，同时主表单两个当前实际值与预期完全一致并稳定至少 300 毫秒；任一端被覆盖、回滚或未提交到表单都会失败。
6. `output` 仍为两个实际值组成的列表，如 `["2026-10-17 09:10:11", "2026-11-17 18:20:21"]`。后续可引用 `{{设置活动时间.output.0}}`、`{{设置活动时间.output.1}}`；可再加 Watch 核验主表单字段，最终 Output 返回实际读值而不是仅回显参数。

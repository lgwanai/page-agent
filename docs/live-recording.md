# 网页录制与直播录制

扩展 0.10.75 起提供“网页录制 / Web Recording”节点和侧栏“录屏与录音”入口。无需配置模型或启动 MCP 服务即可手动录制；扩展 0.10.76 / MCP 服务 0.10.21 将工作流节点改为异步任务，避免 Agent 等待整段录制导致 MCP 超时。扩展 0.10.77 修复显式“保持当前页面”仍等待直播页全部加载的问题，已播放的直播可直接进入异步录制。升级时需同时更新扩展和 MCP 服务，重启已运行的共享桥接服务，并在侧栏核对实际加载版本。

## 直接录制直播

1. 在 Chrome 打开具体直播间，等待画面播放，并在播放器中取消静音。抖音可能默认静音，网页看得到画面不代表有声音。
2. 在该直播页点击工具栏的 Page Agent 图标。使用浏览器菜单打开侧栏不能替代这次调用。
3. 点击“录屏与录音”，选择画面和声音或仅声音，设置 1–1800 秒和文件名。
4. 点击“开始录屏”，检查“已检测到网页声音”和分块增长。侧栏可关闭，也可切换标签页。
5. 到时自动停止、保存；也可提前点击“停止并保存录屏”。成功后显示本机路径，可点击“在文件夹中显示录制”。

文件保存在 Chrome 下载目录下的 `PageAgent` 文件夹，文件名自动追加唯一录制 ID。WebM 视频使用 VP8/Opus，仅声音使用 Opus。格式与真实编码一致，不把 WebM 改后缀冒充 MP4。

## 工作流节点

| 字段 | 说明 |
| --- | --- |
| `kind` | `mediaRecording` |
| `action` | `record` 异步定时录制；`start` 异步开始；`stop` 发起停止与后台保存；`status` 读取快照 |
| `mode` | `videoAudio` 画面与网页声音；`audio` 仅网页声音 |
| `durationMs` | 1000–1800000；`start` 时也是自动停止上限 |
| `fileName` | 文件基础名称，支持变量；路径字符会被替换 |
| `recordingId` | `stop` / `status` 可引用开始节点的 `id`；留空使用本次工作流的目标标签页 |

```json
{
  "id": "recording1",
  "name": "直播录制",
  "kind": "mediaRecording",
  "action": "record",
  "mode": "videoAudio",
  "durationMs": 180000,
  "fileName": "直播-{{主播}}",
  "recordingId": ""
}
```

打开直播页并调用扩展后，开始节点开启“保持当前页面”。MCP 可以创建和运行录制节点，但不会自动授予新网页采集权限；跨站导航、新标签页通常需要用户再次调用扩展。

开始与停止之间可以继续执行网页节点。停止节点的录制 ID 可填写 `{{开始录制.id}}` 或 `{{开始录制.output.id}}`，以避免页面切换后停止错误的录制。每个插件实例同时只允许一段录制。

### Agent 异步调用

`record` 和 `start` 都在启动并注册任务后立即走成功出口，返回录制 ID 和状态 URL，不等待录满或磁盘保存。成功出口表示任务已受理；最终录制成功以状态接口为准。后续 Output 节点应返回 `{{直播录制.statusUrl}}`，也可返回完整录制节点对象。

初始输出示例（令牌与 ID 仅为结构示意，实际使用运行返回的值）：

```json
{
  "type": "mediaRecording",
  "id": "recording-id",
  "state": "recording",
  "taskId": "task-id",
  "statusUrl": "http://127.0.0.1:17373/recordings/<随机令牌>",
  "expiresAt": "2026-11-04T05:00:00.000Z",
  "pollAfterMs": 2000
}
```

Agent 在运行 MCP 的同一台电脑每 2 秒 GET `statusUrl`。查询不等待整段录制或文件保存；目标扩展响应最长等 3 秒。`recording` 表示录制中，`saving` 表示正在封装或下载；二者 `done=false`。下载确认成功且文件存在、大小一致后，同一个 URL 返回：

```json
{
  "taskId": "task-id",
  "status": "completed",
  "done": true,
  "success": true,
  "filePath": "/Users/example/Downloads/PageAgent/直播-recording-id.webm",
  "fileUrl": "http://127.0.0.1:17373/recordings/<随机令牌>/file",
  "bytes": 59689384
}
```

`filePath` 是 Chrome 确认保存的绝对路径；`fileUrl` 可供 Agent GET 下载文件，支持 HEAD 和单段 Range。源文件被删除、移动或大小变化会明确返回失败，不虚报完成。视频不进入 Base64、运行历史或 MCP 文本结果中。

- `failed` / `done=true` / `success=false`：查看 `error`。`record` 必须录满指定时长；直播源提前结束或手动停止时，若已保存部分文件，则放在 `partialFile.filePath/fileUrl`，不会当作完整录制成功。`start` 使用自动停止上限，允许显式提前停止并正常完成。
- `unavailable` / `done=false` / HTTP 503：扩展暂时断开或查询超时，稍后重试同一 URL。已确认保存的最终结果不依赖扩展仍然在线。
- HTTP 410：URL 过期。URL 最长有效 24 小时，每个服务保留最近 100 个任务；开始下一段录制不会立刻覆盖上一段任务。
- MCP 客户端断开、工作流结束或取消后，已经受理的录制仍继续。需要停止时执行 `stop` 节点或使用侧栏控制；`stop` 同样只发起停止与后台保存并返回快照，然后继续轮询。后台录制不阻塞后续工作流执行。

任务索引写入本机 `~/.page-agent/recording-tasks-17373.json`，服务重启后原 URL 可继续查询；浏览器关闭、扩展重载或录制后台消失则不能保证恢复采集，重连查询将报告中断。该 URL 包含随机访问令牌，仅监听 `127.0.0.1`，请勿公开分享。远端云 Agent 不能直接访问电脑的回环地址；应由同机客户端拉取或配置明确的本地转接。

手动侧栏录制仍可离线使用，不依赖 MCP；工作流异步录制需要新版 MCP 服务已连接，旧服务会在采集前明确报错。

## 保存与限制

- 录制的是目标标签页画面和声音。弹幕、菜单和网页遮挡可能被录入；其他标签页、麦克风和桌面应用声音不在采集范围内。
- 每秒左右提交录制分块到扩展的本机 OPFS，停止后组合文件交给 Chrome 下载，不通过扩展消息传递整段视频。仅在下载确认完成后删除对应分块。
- 保存失败保留分块并显示错误，可在当前会话重试保存；磁盘空间不足、浏览器崩溃或扩展重载不保证能恢复。本版没有重启后的分块恢复入口。
- 直播页面必须持续播放。登录、付费、受保护内容、断流、系统睡眠和网站暂停策略均可能影响结果。
- 配置上限 30 分钟；实际完成了下述 3 分钟验证，未将其视为数小时稳定性保证。定时和开始操作都由 Offscreen 独立运行，不占用整段工作流调用。
- Chrome 原生录制产生流式 WebM，部分播放器可能不显示时长或无法拖动进度；可用支持 WebM 的播放器打开，需要 MP4 时再转码。

## 最新包抖音异步实录：2026-11-03

扩展 0.10.77 / MCP 0.10.21 使用标准 Chrome 完成公开抖音直播 180 秒录制。MCP 在 101 ms 返回状态 URL，随后断开客户端、关闭侧栏并切到空白页；同一 URL 轮询得到 completed，fileUrl 实际下载 60,242,473 字节，与 Chrome 保存文件 SHA-256 完全一致。媒体时间跨度 179.968 秒，VP8 1920×1080、4,495 帧，Opus 48 kHz 双声道；全文件解码无错误。音视频起点差 26 ms、终点差 8 ms，声音平均 -32.2 dB、峰值 -11.5 dB；不是人工口型同步验收。

实测过程中修复了 Start 显式“保持当前页面”仍等待直播页面 complete 的 30 秒超时。792 项单元/集成测试及 5 条真实 Chromium 录制 E2E 通过，新增持续加载 iframe 场景。Windows 包改为只包含生产依赖，清除构建机 macOS 开发模块；Windows 包/平台分支检查通过，但尚无 Windows 录屏真机验收。

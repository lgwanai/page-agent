# 文档维护

## 内容源与交付物

- `README.md`：项目定位、安装入口和文档导航。
- `CHANGELOG.md`：历史发布记录，保留当时版本限制。
- `docs/guide/`：以任务为单位的使用步骤。
- `docs/nodes/`：完整节点目录与配置指导。
- `docs/reference/`：限制、术语和维护方式。
- `docs/examples/`：可导入的练习 JSON、本地页面与数据。
- `docs/user-manual.html`：由 Markdown 生成的离线手册，不直接编辑。

保持 `docs/` 为唯一文档根目录，不再建立内容重复的 `doc/`。原有专题文件保留路径，目录页负责导航。

## 构建与检查

在安装项目开发依赖后执行：

```bash
npm run docs:build
npm run docs:check
```

构建使用锁定的 Markdown 渲染依赖，不访问远程网站。HTML 内嵌样式、搜索和导航脚本，可直接打开，支持章节跳转、正文搜索、代码复制、打印/保存 PDF。

`docs:check` 检查 Markdown 本地文件和锚点、17 种节点和当前 MCP 工具覆盖、练习 JSON 与源码校验器，以及 HTML 导航/搜索结构和构建内容摘要。检查只使用本地示例，不连接用户 Chrome、不执行网站业务动作。

练习服务：

```bash
npm run docs:serve
```

默认仅监听 `127.0.0.1:4180`，从 `docs/` 提供静态内容，不代理请求，不写入上传文件。可用 `--port=4181` 临时换端口；导入练习 JSON 前同步修改开始网址和请求 URL。

## 更新准则

1. 先核对源码、可见界面、当前模板和已验证行为，再修改说明。
2. 新增节点时，同步更新节点目录、参数/输出说明、限制与 MCP 参考。
3. 修改 UI 操作时同步更新录制/编辑步骤，避免把旧菜单名称写进新手教程。
4. 示例只使用本地练习页面和演示数据；不要放入真实密钥、账号或用户导出文件。
5. 调整文档后重新生成 HTML，检查长表格、代码、窄屏目录和打印视图。

文档构建从 manifest/package 读取实际版本，不人为修改插件版本。只有插件代码新发布时才按仓库规则递增 patch 并同步 manifest 与锁文件。

## 历史资料

`enterprise/` 和早期企业 HTML 属于历史评估基线。保留其原始版本与日期，不能仅替换版本号后声称完整重审；当前用户操作以新手册为准。

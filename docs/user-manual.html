建议学习顺序#

  1. 按快速上手操作本地练习页，完成一次录制和一次手动运行。
  2. 阅读参数与变量，把固定输入替换成可复用参数。
  3. 通过输出节点返回结果，再学习失败出口与业务成功标记。
  4. 按业务选择检索、循环、分页、请求或文件处理等节点。
  5. 手动验证稳定后，再接入 MCP；使用目标实例、工作流 ID 和密钥调用。

节点分类#

当前有 17 种节点类型；“开始”自动创建，“调用流程 / Action”保留兼容，其他 15 种可从新增节点菜单选择。

  • 网页操作与定位：网页操作、文件上传、定位修复和 iframe。
  • 数据读取与结果：检索、监控、数据表、表格填充和输出。
  • 流程控制：开始、等待、循环、分页、失败分支和兼容 Action。
  • 请求：HTTP/HTTPS、Text/JSON、请求头、请求体和变量。
  • 弹窗与日历：原生确认框、输入框、离开页面确认与日期时间。
  • 截图、邮件与智能分析：文件输出、附件、本机配置与模型调用。

选择安装方式#

方式适用场景包含内容
扩展 ZIP已有 MCP 环境，或只录制、编辑、操作网页Chrome 扩展；不包含 Node、MCP 服务或网站账号
便携交付包获得维护者提供的 Windows/macOS 完整包以实际包为准，通常包含扩展、Node、MCP 服务与 Setup
源码构建开发、自行部署、Linux 环境在本机安装依赖并生成扩展和 MCP 服务

不要把扩展 ZIP 当作完整便携包。便携包与扩展的可用版本可能不同，应核对包内实际版本，不能仅根据文件名推断已更新。

安装扩展 ZIP#

  1. 将扩展包完整解压到固定目录，保留目录内的 manifest.json 和其他文件。
  2. 打开 Chrome 的 chrome://extensions，开启“开发者模式”。
  3. 选择“加载已解压的扩展程序”，选择直接包含 manifest.json 的目录。
  4. 从扩展菜单打开 Page Agent 侧栏，确认顶部显示版本 0.10.66。
  5. 打开要操作的 HTTP/HTTPS 网页，确认登录状态和账号正确。

源码构建加载的是 dist/；完整便携包通常加载其 extension/。扩展不从 ZIP 压缩文件直接运行。

便携包#

Windows 运行包内 Setup.cmd；macOS 运行 Setup.command。Setup 在本机生成 page-agent-mcp.json，然后将该配置导入 MCP 客户端，手动加载包内扩展目录。

便携包无需再执行 npm install 或构建。移动解压目录后，重新运行 Setup 并更新 MCP 客户端配置。不要将另一台电脑生成的 Node 路径、脚本路径直接复制过来。

芯片和系统应与实际交付包匹配。详细说明见 跨系统 MCP 部署。

从源码构建#

准备 Node.js 20 或更新版本和 npm，在项目根目录执行：

bash
npm ci
npm run build
npm --prefix mcp-server ci
npm run mcp:build

加载 dist/ 后，如需接入 MCP，在同一台电脑、同一项目位置执行：

bash
npm run mcp:config

将输出中的 page-agent 条目合并到客户端已有的 mcpServers 中。服务路径必须是实际生成的 mcp-server/dist/index.js，不能填写 TypeScript 源文件。

升级并确认生效#

  1. 导出重要工作流作为备份；确认没有工作流正在执行。
  2. 替换当前扩展目录内容，或加载新的解压目录。
  3. 在扩展管理页点击“重新加载”，重新打开侧栏并核对版本。
  4. 刷新需要录制或回放的网页，让内容脚本与新扩展一致。
  5. 更新 MCP 路径后，在 MCP 客户端重启对应服务；新请求节点模板需要服务 0.10.17。

“重新加载”使用原加载目录，不会自动改为另一个下载目录。通常同一扩展身份和 Chrome 配置文件内的数据可继续使用；卸载、换配置文件或改变扩展身份可能导致看不到原数据，因此先导出备份。

安装完成检查#

  • 侧栏可打开，版本与预期一致。
  • 可以创建空白工作流，看到开始节点。
  • 在练习网页可以选择控件、录制并保存。
  • 需要 MCP 时，侧栏 MCP 状态已连接，客户端能列出目标实例。

03 / 开始使用

快速上手

使用本地练习页跑通首个流程

本章目录
打开练习环境路径一：录制创建路径二：直接导入练习流程给流程添加返回值下一次复用

目标：在无真实业务提交的本地练习页上，跑通“填写姓名 → 显示结果 → 返回文本”。普通网页流程不需要配置 AI；路径上传和 MCP 调用另需本机 MCP 服务。

打开练习环境#

以下练习服务需要源码目录与 Node 环境。只有扩展 ZIP 时，也可在自己的测试网页按录制步骤操作，或请维护者提供练习页面。

在项目根目录启动仅用于文档练习的静态服务：

bash
npm run docs:serve

在 Chrome 打开 http://127.0.0.1:4180/examples/practice.html，然后打开 Page Agent 侧栏。练习页不发送表单或上传文件到服务器，姓名仅用于页面显示。服务停止使用 Ctrl+C。

已有其他静态 HTTP 服务时，也可用其托管 docs/examples/。扩展操作需要 HTTP/HTTPS 页面，不使用 file:// 打开练习页。

路径一：录制创建#

  1. 侧栏点击“创建工作流” → “录制网页操作”。
  2. 在练习页“姓名”输入框填写“张三”，点击“显示问候”。页面出现“你好，张三”。
  3. 点击侧栏“停止录制并编辑”，进入画布。
  4. 选择节点后点击下方“展开属性”，核对输入和点击是否正确。
  5. 检查开始节点的目标网址；配置网址时，每次运行会重新打开该页。
  6. 点击“保存工作流”，取名“练习问候”。
  7. 返回列表并运行，确认网页显示与预期一致。

录制结果是可编辑的操作序列，业务判断、错误分支和最终结果仍需按需求补充。录制文件选择等操作后，应核对相应节点是否配置完整。

路径二：直接导入练习流程#

  1. 下载或找到 问候练习 JSON ↓。
  2. 在工作流列表点击“导入 JSON”，选择该文件。
  3. 保持练习服务运行，检查开始节点网址为上述练习页地址。
  4. 点击“运行画布”，在参数窗口填写 姓名，再点击“开始运行”。
  5. 查看结果中的 output，应为 你好，您填写的姓名。

导入流程包含开始、输入、点击和输出节点。DOM Selector 分别为 #name、#greet 和 #result，便于对照页面理解。

给流程添加返回值#

  1. 从点击节点的成功连接点添加“输出 / Output”。
  2. 展开属性，来源选“网页 DOM”，选择练习页结果区域。
  3. 读取方式选“文本”，业务结果按需要设为成功或中性。
  4. 运行后检查逐节点日志及最终输出，再更新工作流。

点击事件成功只说明操作执行情况；输出或监控节点可以补充页面结果验证。ok 表示执行状态，businessOk 表示显式配置的业务结果，详见 运行与调试。

下一次复用#

手动运行会按开始节点的声明收集参数；MCP 调用则在 data 中传入同名字段。不要为了更换姓名重新录制。

画布与属性#

点击节点只选中节点；下方出现属性条，点击“展开属性”显示详情，点击“收起属性”折叠。选中其他节点或拖动节点、画布时，属性详情会收起。属性条仍保留当前选中节点。

节点类型使用中文主标题与英文副标题。业务节点名称可自行修改，但它也是变量引用标识；修改后同步检查所有引用该名称的表达式。

新增与连接#

操作使用方法
新增节点左侧四格图标打开类型菜单，在当前画布视野创建节点
添加后续节点点击节点右侧相应连接点，选择类型，自动创建连线
网页操作选择类型后，到目标网页点击控件，创建定位信息
删除节点选中并展开属性，点击删除；开始节点不能删除

新增的独立节点需要连接到入口路径才会执行。成功/失败出口不是同时运行的两条并行路径；执行器按实际结果选择一个出口。

循环与分页内部画布#

容器内的入口图标是虚拟入口，不保存为业务节点。通过“添加内部节点”或内部连接点构建子流程，连线不能跨容器。

容器会按内部内容扩展尺寸，随主画布统一缩放。新循环每次遍历自动执行内部路径，末尾无需回连；外部“完成”出口连接后续节点。旧版外部回连循环仅作为兼容模式保留。

撤销与重做#

操作WindowsMac
撤销Ctrl+ZCommand+Z
重做Ctrl+Shift+ZCommand+Shift+Z

右上角按钮悬浮显示当前系统快捷键。输入框、文本区域和对话框保留文本编辑行为，不触发画布历史。运行、保存、整理期间不响应画布快捷键。历史属于当前编辑会话，不能作为跨设备或跨会话的备份；自动整理作为一次图更新支持撤销。

录制的推荐步骤#

  1. 先到达要录制的业务入口，关闭不相关的临时弹层。
  2. 启动录制，按正常业务顺序操作，留意网页悬浮录制状态。
  3. 停止录制并核对节点，移除误点，补充参数、监控、输出和失败分支。
  4. 原生 confirm/prompt 等应使用明确的弹窗节点配置，不依赖一次录制碰巧自动应答。
  5. 运行验证并保存；之后重新打开，确认参数化流程仍可执行。

保存与恢复草稿#

“保存工作流 / 更新工作流”才更新正式工作流库。未保存编辑会单独备份为本机恢复草稿；侧栏重新打开时可恢复或丢弃，不代表已经发布为正式流程。

返回列表时留意未保存提示。MCP 编辑接口按接口语义直接保存，与手动画布的草稿机制不同。

声明运行输入#

在开始节点配置参数名称、类型、是否必填和说明。名称必须与手动表单或 MCP data 的字段一致。

类型用途示例
文本 string姓名、关键词、路径、日期张三
数字 number数量、金额、页码10
列表 array字符串、数字等非对象项列表["A", "B"]
对象 object一组键值字段{"编号":"001","金额":20}
对象列表 objectArray多行表格或业务记录[{"编号":"001"},{"编号":"002"}]

界面没有独立的布尔参数类型。需要布尔值时可放入对象字段，例如 {"启用":true}，再引用 {{选项.启用}}。列表与对象列表的类型不同，不要混填。

手动运行支持结构化编辑与 JSON 输入。上次手动参数按工作流保存在本机，MCP 调用不会读取这些记忆，只使用本次传入的数据。

表达式#

写法含义
{{姓名}}读取同名运行参数，或前置节点的输出
客户：{{姓名}}拼接为文本
{{请求结果.output.id}}从前置节点输出读取字段
{{数据表.rows}}读取数据表节点的行列表
{{当前项.编号}}读取循环当前对象的字段
{{列表.0}}通过点号访问数组下标

独立引用会保留对象、数组、数字等类型；与固定文字拼接会得到字符串，对象按 JSON 序列化。表达式不是 JavaScript，不支持 +、函数调用、条件运算或 arr[0] 这类语法。

运行参数与节点名称相同会产生覆盖歧义；建议使用不同名称，并避免在名称中使用点号。缺失变量在部分文本插值中会变为空文本；输出等严格来源会报错，因此运行前检查声明和执行顺序。

节点输出#

只有已经执行的节点才有可引用的输出。通常 {{节点名称}} 与 {{节点名称.output}} 都可以读取结果；读取字段时优先采用显式的 .output 写法。

例如，请求节点名为“读取记录”，返回：

json
{"id":7,"name":"张三"}

后续输入节点可填写 {{读取记录.output.name}}。输出节点可选择“前序节点”，路径填写 name，返回对应字段；路径相对节点的输出，不再加 output.。

文件输出是专用对象，必须独立引用，不能拼成 附件：{{截图}}。邮件附件可填写 {{页面截图}}，数据表 Excel 可填写 {{数据表.excel}}。

循环作用域#

循环配置当前项变量和索引变量，例如“当前项”“索引”。内部流程使用这两个变量，外层同名变量在循环结束后恢复。循环节点整体输出不能作为所有迭代结果的自动汇总；需要按业务自行设计输出或外部收集。

分页的当前页变量同样只在内部流程执行时覆盖。结果终止表达式需要独立变量引用，例如 {{本页匹配.output}}。

列表与查找#

首页显示已保存的工作流。可按名称、描述、标签或 ID 搜索，按最近修改、最近使用、名称排序，并按标签筛选。标签最多 10 个，每个 1–30 个字符。

ID、名称与密钥#

标识含义

复制与重命名#

“复制为新工作流”创建独立流程，使用新的工作流身份。重命名工作流不会把它当作另一份流程；业务节点名称仍需单独修改。

建议先复制再做较大的业务改造，以便保留原来的稳定版本。撤销不是工作流版本管理系统。

导入导出与迁移#

  1. 更多菜单选择“导出”，保存 .page-agent.json 文件。
  2. 在目标环境“导入 JSON”，检查开始网址、参数和站点定位信息。
  3. 导入后重新核对 MCP ID 和密钥，再运行验证。

导出包含节点、连线和显式填写的配置，不包含工作流访问密钥、全局 AI Key、SMTP 账号配置或手动参数记忆。若在请求头、节点正文等字段硬编码令牌或个人信息，这些显式内容仍会导出。

导入遇到无效 ID 或本机已有 ID 时会生成新的 UUID；无论是否保留原 UUID，本机密钥都应以导入结果为准。不同电脑的登录态、本地文件路径和服务配置不会随 JSON 自动迁移。

删除与恢复#

“删除工作流”先移入回收站，暂停该工作流调用。可在首页“回收站”恢复，恢复保留原 ID 和密钥；彻底删除后不能从插件恢复。

当前回收站没有按天数自动清理的规则，不需要为了保留流程定期恢复。要长期归档，请另外保存导出的 JSON。

删除节点在属性详情操作：删除容器会包含其内部节点，关联连线会清理，不会自动把前后节点接起来。MCP 提供独立 delete_page_node；开始节点和不存在的节点不能删除，残留显式引用会阻止删除。

并发编辑#

MCP 修改使用最新 expectedUpdatedAt 防止覆盖其他客户端编辑。遇到版本冲突时重新读取并合并，不要用旧版本重复提交。手动画布打开期间被 MCP 或 Selector 升级修改的流程，也应检查最新状态再保存。

单节点调试不会自动打开开始节点的目标网址。先手动准备页面，或单独调试开始节点。调试循环或分页容器会执行内部流程，不能把它当作只读校验。

开始与页面状态#

开始节点配置了目标网址时，每次完整运行会重新打开该网址，即使当前地址看起来相同。只想继续使用已打开的 SPA、抽屉或 iframe 状态时，使用“保持当前页面，不刷新”。

普通 URL 校验和强校验控制最终地址匹配范围；等待登录选项用于人工完成登录后继续。页面加载完成不等于业务数据已经出现，必要时添加监控或等待。

成功、失败与业务结果#

  • 普通节点从成功或失败出口继续，没有失败连线时错误通常中止当前流程。
  • 循环和分页容器从完成或失败出口继续。
  • 失败被后续分支正常处理后，整个流程仍可能 ok: true。
  • 输出节点的业务结果独立记录为 businessOk；任一显式失败标记优先。
json
{
  "ok": true,
  "businessOk": false,
  "output": "未找到符合条件的记录"
}

这表示执行器按设计走完了流程，但业务目标未达成。不要仅凭 ok: true 判断订单、上传、发送等服务器端业务已经成功。

查看结果#

运行时画布标记当前节点，结束后可查看节点日志和运行结果。重点查看：

字段用途
steps每个节点的结果与输出端口
data单步输出，例如查询列表、文本、JSON、文件
verification预期、实际状态及验收说明
diagnostic错误码、阶段、上下文与处理建议
output / outputs最后一个输出节点的值，以及按名称汇总的值
cancelled是否因停止运行而结束

没有执行输出节点时，不会自动生成业务级 output。循环内同名输出通常保留最后一次值，不代表自动收集了全部迭代数据。

停止与运行历史#

“停止运行”会中止可取消的等待和请求，并阻止后续节点继续。已经完成的网页操作、上传或服务器处理不会自动回滚。

运行历史按工作流保存最近摘要，当前上限为每个流程 20 条、总计 200 条且整体约 2 MB。摘要包含参数名称/类型和步骤消息，不保存完整参数值及页面输出；错误消息和业务步骤名仍可能含业务信息。

推荐排错顺序#

  1. 找到第一个失败节点，先看错误码和实际结果。
  2. 核对当前页面、登录、frame 和前置节点是否真的执行。
  3. 用检索、读取或单节点调试缩小范围，避免反复运行整段流程。
  4. 结果未知时先确认页面或服务器状态，再决定是否重跑。

连接关系#

Agent 客户端通过 stdio 启动本机 MCP 服务，服务通过本机桥接连接 Chrome 扩展。浏览器中的业务登录态保留在目标 Chrome 配置文件内。

text
Agent 客户端 → stdio MCP 服务 → 本机桥接 → Chrome 扩展 → 目标网页

ws://127.0.0.1:17373/extension 是插件连接地址，不是应填写到客户端的 HTTP MCP 地址。插件不能自行启动 Node 服务；“重试连接”也不能代替启动服务。

配置流程#

  1. 便携包运行 Setup，或源码环境按 安装与升级 构建服务。
  2. 在本机生成 page-agent-mcp.json，或在插件“MCP”面板导入本机配置。
  3. 将 JSON 的 page-agent 条目合并到客户端的 mcpServers；保留其他已有服务。
  4. 在客户端启用/重启服务，回到侧栏确认 MCP 已连接。
  5. 用 list_page_agent_instances 选择目标实例，再读取或运行目标流程。
json
{
  "mcpServers": {
    "page-agent": {
      "command": "<本机 node 或 node.exe 完整路径>",
      "args": ["<本机 mcp-server/dist/index.js 完整路径>"],
      "env": {"PAGE_AGENT_BRIDGE_PORT":"17373"}
    }
  }
}

JSON 字符串中的 Windows 反斜线需要转义；优先使用 Setup 或 npm run mcp:config 生成配置。路径含空格时不要在字段内部额外加引号，也不要把 npm.cmd 当作 Node 可执行文件。

多个客户端可共享桥接。更新版本或移动目录时，重新生成本机配置并检查面板显示的实际服务路径；停止旧桥接前确认没有流程在执行，不要结束所有 Node 进程。

调用已保存流程#

json

  "instanceId":"<目标 Chrome 实例>",

  "key":"<该工作流密钥>",
  "data":{"姓名":"张三"}
}

创建与修改#

推荐顺序：get_page_workflow_toolkit → create_page_workflow → inspect_page_content → edit_page_workflow → validate_page_workflow → 单节点调试 → 完整调试。

先读取工具包获取当前节点模板和端口。每次修改前读取最新 updatedAt，以 expectedUpdatedAt 提交；冲突时重新读取和合并。修改接口会直接保存，不需要再点击侧栏保存。

delete_page_node 可删除指定节点并清理关联连线；容器删除包含内部节点，不自动重连前后节点。当前工具清单没有独立的工作流删除工具；删除整个流程使用侧栏“删除工作流”。

text

json

检索 · Query#

选择一个 DOM 范围，设置候选元素、读取方式和匹配条件，返回匹配元素列表。常见设置：

字段使用方法
候选元素如 tr、.item；相对所选范围
候选内部读取位置如 :scope > td:nth-child(2)，只比较该列、仍返回整行
读取来源文本、当前值、属性
匹配存在、完全相同、包含、正则
无匹配出口默认成功并返回空列表；可配置为失败分支
返回上限可配置 1–500 个，防止下游处理过大

返回项包含 Selector 和元素身份信息，可交给循环或后续节点。候选内的读取位置需唯一；歧义会失败，缺少该位置的候选会跳过。正则模式与 flags 应先用小范围数据验证。

监控 · Watch#

反复读取目标的文本、值或属性，直到满足条件或超时。已满足时立即继续；否则按照配置间隔检查。适合等待“导出完成”“上传成功”、按钮启用等可观察状态。

最长等待 100–3600000 毫秒，检查间隔 100–10000 毫秒。固定等待只是延迟，监控才是在确认条件；不要用延长等待掩盖错误定位。

数据表 · DataTable#

选择唯一原生 table、其单元格或仅包含一个 table 的容器。表头可自动、第一行或无表头，纯数字解析会尽量保留前导零和长编号。

输出包括 columns、rows、values、rowCount；启用 Excel 时还有 excel 文件对象。

text
{{数据表.rows}}
{{数据表.excel}}

只读取已存在于当前 DOM 的行；分页和虚拟滚动中尚未加载的数据不会自动补齐。纯 div 虚拟表格不等同于 DataTable 支持的原生表格；按页读取需另行设计结果汇总。

表格填充 · Table Fill#

选择完整表格区域，提供对象列表或带 rows 的数据表结果，并设置至少一个 key 列。执行器按列名/键匹配目标行，再写入可编辑字段。

  • key 列不改写，只用于匹配；只读或禁用列会跳过。
  • 可按业务决定是否跳过未匹配行。
  • 原生 table、ARIA、ul/li 和部分 div/分离表头结构可识别；必要时配置表头、行、单元格 Selector。
  • 不自动提交；失败前已填内容不会自动回滚。

开始 · Start#

每个流程有一个开始节点，不能删除。配置输入声明、目标网址、页面加载超时、稳定等待、登录等待和最终 URL 校验。

配置目标网址意味着每次完整运行重新导航；“保持当前页面，不刷新”用于继续已准备好的页面状态。普通/强校验决定匹配方式，不决定是否刷新。详见 运行与调试。

等待 · Wait#

支持固定或随机等待，范围为 0–60000 毫秒的整数。随机模式设置最短和最长时长，两者都要有效且最短不大于最长。

当页面有明确完成状态时优先使用监控；等待节点不证明页面数据已经加载或业务已经完成。停止运行会取消等待。

循环 · Loop#

  1. 数组来源填写列表参数、检索输出或数据表行列表，例如 {{记录列表}}。
  2. 配置当前项和索引变量，例如“当前项”“索引”。
  3. 在内部画布添加每项处理步骤，从内部入口连接完整路径。
  4. 内部普通节点末尾无需连回循环容器。
  5. 容器外的完成出口连接循环之后的步骤，失败出口连接错误处理。

例如内部输入值使用 {{当前项.编号}}。最大遍历次数用于防止意外处理过多数据；内部页/项执行仍受全流程 1000 步的总预算约束。不要将循环输出理解为所有项结果的自动聚合。

旧版无 body 的外部回连循环保留兼容；新流程使用内部子流程形式。

分页 · Pagination#

选择包含页码与上下页按钮的完整分页容器。两种模式：

模式行为
到指定页到达并校验目标页，执行一次内部流程；内部可为空
遍历每一页从第 1 页开始，逐页执行非空内部流程，再翻到下一页

可用当前页变量，默认 page。正常结束条件可选到指定页后结束，或内部结果变量非空；最大页数是安全上限，到上限但仍有下一页会报告未完成，不能当作正常终止页。

翻页通过实际当前页确认。若网站数据在页码更新后延迟加载，应配置稳定等待或内部监控。内部节点不应私自改变当前页。

完整配置见 分页与内部子流程。

失败分支#

普通节点 failure 可以连接到输出、截图或其他处理步骤。失败分支处理完毕后，整个执行可能成功结束；业务目标是否达成需要用输出节点业务标记表达。

失败连线不是自动重试配置。对可能已经提交的操作，应先确认结果，避免盲目循环再次提交。

调用流程 · Action（兼容）#

新用户优先使用工作流与容器内部子流程，不要按历史文档寻找已移除的“保存 Action”按钮。

请求

HTTP/HTTPS 与 Text/JSON 返回

本章目录
操作步骤练习：读取本地 JSON结果与失败

请求节点用于调用链接/API，返回 Text 或 JSON。它由扩展后台发送，不通过网页点击，也不自动继承网站 Cookie；可通过请求头提供服务需要的认证值。

操作步骤#

  1. 新增“请求”，连接到需要执行的路径。
  2. 展开属性，填写完整 HTTP/HTTPS URL。
  3. 选择方法与返回类型；需要 JSON 请求体时设置 Content-Type。
  4. 按需填写 JSON 对象形式的请求头、文本或变量请求体和超时。
  5. 单节点调试查看返回值，再连接输出节点将结果作为工作流输出。

Text 直接返回字符串；JSON 保留对象、数组、数字、布尔值或 null 类型。JSON 模式下空响应和无效 JSON 会失败，不会默默退回文本。

练习：读取本地 JSON#

启动 npm run docs:serve 后，导入 请求练习 JSON ↓。流程从本地练习页开始，请求：

text
http://127.0.0.1:4180/examples/sample-response.json

输出应包含 message: "请求练习成功" 和记录列表。后续可用 {{读取练习数据.output.records.0.name}} 访问第一条记录名称。

结果与失败#

成功要求 HTTP 2xx 且按指定类型读取完成。HTTP 状态错误、网络问题、超时和解析失败走失败出口。超时包含读取响应体；停止运行会中止当前请求并阻止后续节点。

服务器可能在连接中断前已处理写入，因此请求不自动重试。请求节点的 URL、请求头或正文若硬编码令牌，也会出现在导出的工作流中。

方法、字段、POST 示例与 MCP 说明见 请求详细配置。

哪些操作会外发数据#

  • 网页操作沿用当前浏览器会话，可能向业务网站提交数据。

  • 智能分析节点向已配置模型发送选定输入和指令。
  • 邮件节点通过配置的发送服务发送正文与附件。
  • MCP 客户端收到页面信息、调试输出或截图后如何使用，取决于客户端本身。

没有使用相应节点时，不应把这些外发能力理解为自动发生；但交给 Agent 的工具权限与工作流密钥需要按实际用途管理。

导出与共享#

工作流导出不包含全局 AI/SMTP 配置及工作流访问密钥。但节点 URL、请求头、正文、固定输入与 Selector 中显式填写的内容属于工作流，会一起导出。

推荐把频繁变化或敏感的业务值设为运行参数；分享前检查导出文件，复制运行 Prompt 时留意其中包含工作流密钥。

调用与页面边界#

同一插件实例不能并发执行多个流程。工作流 ID、实例 ID 与 key 分别标识流程、目标浏览器和访问凭据；它们不能替代目标网站的账号权限。

密码和隐藏输入等页面读取存在保护，但页面可见文字、截图、业务日志仍可能包含敏感信息。网页返回的文字与 HTTP 内容是业务数据，不应被 Agent 当作新的系统指令。

流程调试、上传、邮件和 HTTP 写入都可能产生真实影响。停止只阻止后续执行，不能撤销服务器已处理的业务。

请求字段参考

方法、请求体、响应与 MCP

本章目录
配置

从画布左侧“新增节点”选择“请求”，展开属性，配置请求链接与返回类型。URL、请求头的值和请求体支持工作流变量。请求由扩展后台发送，支持跨域 HTTP/HTTPS 和自定义端口，默认不携带网页 Cookie。

配置#

字段含义
url完整 HTTP/HTTPS 链接，支持 {{变量}}
methodGET、POST、PUT、PATCH、DELETE、HEAD、OPTIONS
headersJSON 对象文本，值必须为文本，可引用变量
body请求体文本；单独引用对象变量时自动序列化成 JSON；GET/HEAD 留空
responseTypetext 返回原始文本；json 解析为对象、数组、标量或 null
timeoutMs100–300000 毫秒，默认 30000；包含读取响应体的时间

例如发送 JSON：

json
{
  "id": "request1",
  "name": "创建记录",
  "kind": "request",
  "url": "https://example.com:8443/api/records",
  "method": "POST",
  "headers": "{\"Content-Type\":\"application/json\",\"Authorization\":\"Bearer {{令牌}}\"}",
  "body": "{{记录}}",
  "responseType": "json",
  "timeoutMs": 30000
}

后续节点用 {{创建记录.output}} 或 {{创建记录}} 读取完整返回内容，用 {{创建记录.output.id}} 读取字段。可连接输出节点的“前序节点”或“变量”来源，把结果作为工作流返回值。JSON 类型保留，不转换为字符串。

成功条件是 HTTP 2xx 且按配置完成响应解析。HTTP 错误、网络失败、超时、JSON 解析失败走失败出口。空响应需要选择 Text；JSON 模式不会把空响应或无效 JSON 当作成功。执行日志记录 HTTP 状态码与返回类型。

停止运行会中止正在进行的请求，也会阻止后续节点执行；已经在服务器处理的请求不会回滚。请求不自动重试，写入请求遇到超时或连接错误时，应检查服务器结果后再决定是否重新运行。

MCP get_page_workflow_toolkit 提供 templates.request 和 httpRequest 说明，创建、编辑、调试、运行、导入导出使用现有工作流工具。需要 MCP 服务 0.10.17 或更新版本。

原生弹窗参考

触发、应答、来源校验与示例

本章目录
MCP 示例

扩展 0.10.60、MCP 0.10.16 新增 dialog 节点。画布工具栏和后续节点菜单均可添加“浏览器弹窗 / Browser Dialog”；已有网页节点的属性中可点“转为浏览器弹窗节点”，保留 ID、连线、事件及完整 Selector/iframe 定位信息。

节点同时负责触发和应答：先监听原生弹窗，再执行所选控件的事件一次，最后核验 Chrome 返回的弹窗关闭结果。请用它替换原来的触发点击节点。不要在前面另放一次触发点击；confirm/prompt 会阻塞网页，等点击完成后才监听会来不及。

类型确定取消
alert关闭提示框不适用
confirm网页收到 true网页收到 false
prompt网页收到配置的文本，可为空网页收到 null
beforeunload允许离开页面留在当前页面

设置项：

  • target、event：触发弹窗的网页控件与操作，默认点击。支持现有稳健定位、自动修复和 iframe 定位。不支持在此节点内上传文件。
  • dialogType：上述四种原生弹窗类型之一。
  • action：accept（确定）或 dismiss（取消）。alert 只允许 accept。
  • message：留空接受任意弹窗文字；填写后精确匹配，支持 {{变量}}；引用不存在的变量会在触发前失败，不会放宽为任意文字。有保存的目标文档 URL 时也核对弹窗来源。
  • promptText：prompt 确定时输入的文本，支持变量和空字符串。取消时不传输入内容。
  • timeoutMs：从监听到触发及完成应答的总等待时间，默认 10000，范围 100–300000 毫秒。

取消是按配置完成的操作，走成功出口。弹窗未出现、类型/文字/来源不匹配、应答失败或实际关闭结果不一致时走失败出口。不匹配时不自动应答，应先人工检查；触发操作不会自动重试。运行停止会释放监听和调试连接。

输出示例：

json
{"type":"confirm","message":"确认操作？","accepted":false,"url":"https://example.com/form","trigger":"clicked"}

prompt 还提供 promptText（仅确定时）与 defaultPrompt。可用 Output 节点引用前序弹窗节点输出的 accepted 或 promptText。已有 alert 自动确定行为继续可用；需要校验文字时改用明确的弹窗节点。

离开页面确认框依赖浏览器允许弹出，通常需要页面此前有真实用户交互。浏览器显示的 beforeunload 提示文字由浏览器决定，建议 message 留空。确定后旧文档的扩展消息可能随导航断开：只有 Chrome 已确认该 beforeunload 按配置关闭，节点才将此类断开视为允许导航的结果；不会重发点击，也不代表新页面业务完成。需要验证到达目标页面时，在后面连接 Watch/Query 等节点。

网页中用 HTML/CSS 实现的自定义弹层、系统文件选择器、浏览器权限请求和 HTTP 认证窗口不属于 JavaScript 原生弹窗；网页弹层继续用 Selector，文件选择使用上传节点。

适用范围与兼容性#

日历节点仍使用 kind: "calendar"、date、endDate、mode，不改变工作流 JSON 字段。

  • YYYY-MM-DD 仍走原有日期选择逻辑，原有 Aurora、Ant/通用单日、区间和内嵌日历测试保持通过。

界面配置识别和安全校验JSON 与 MCP

当前操作已按扩展 0.10.66 / MCP 0.10.17 核对。

界面配置#

  1. 在开始节点或其他节点的右侧连接点添加“分页”。
  2. 点击“选择分页容器”，选择包住页码和上下页按钮的完整 DOM，不能只选择某一个箭头。
  3. 选择“到指定页”或“遍历每一页”。目标页支持 {{page_number}} 等输入变量。 遍历时可设置“终止条件 → 到指定页码后结束”，填写 10 或 {{last_page}}，处理完该页后正常走完成出口。如果页面不足指定页数，遇到实际末页也正常结束。默认仍遍历到末页。
  4. 点击容器内“添加内部节点”，配置每页需要运行的操作。选中内部节点后，点击下方“展开属性”编辑设置；内部节点右侧连接点继续添加分支或后续节点。
  5. 完成出口连接分页之后的流程，失败出口连接恢复 / 通知流程。不配置失败出口时中止。

指定页模式到达并校验目标页后，执行一次内部流程（也可以留空）；遍历模式从第 1 页开始，每页执行内部流程，再翻到下一页。当前页变量默认 page，可在内部节点中使用 {{page}}。运行后还原外层同名变量，支持嵌套。

循环同样有内部画布：每个数组项执行一次内部流程，提供当前项和索引变量，内部末尾无需回连；旧版没有 body 的循环仍使用原来的外部回连逻辑。

识别和安全校验#

  • 当前页通过容器数据属性、选中状态、ARIA 或“当前 / 总页数”文本读取；不根据点击事件是否发送判定成功。
  • 可见目标数字按钮优先；目标页被省略时使用上下页按钮。
  • 图标方向通过按钮及其后代的 class、title、ARIA、图片名称等信息识别；一对无标签箭头可按排列推测方向，但实际翻页必须通过页码验证。
  • 若实际方向错误，先尝试数字按钮或另一个箭头恢复原页，并记录实际方向；恢复失败则停止，不继续盲点。
  • 末页需通过总页数或下一页按钮禁用状态确认。无法确认不会假装全部完成。
  • 最大页数和导航操作数、每次翻页超时、翻页后稳定等待均可配置。达到上限仍有后续页视为未完成。
  • 内部节点不得私自改变当前页；每页子流程执行后会重新检查。全流程最多 1000 个节点执行步，子流程最多嵌套 8 层。
  • 子流程可能产生真实业务影响，重跑前应查看当前页与节点日志。站点在分页操作之后延迟加载数据时，应配置适当稳定等待或内部等待节点。

分页不调用 AI。Canvas、无当前页状态的自绘控件、极特殊分页结构不保证可识别，需根据诊断重新选容器或调整流程。

配置MCP 返回“未取数完成”分支

在画布工具栏或节点出口的添加菜单选择 Output。所有输出节点均可命名、保存、导入导出，并通过 MCP 创建和调试。

配置#

输出来源 source配置方式返回类型
text 文本value: "未成功"，或 "任务状态：{{状态}}"字符串
variable 变量value: "{{data}}" 或 "{{查询.output}}"，必须独立引用保留数字、布尔、null、对象、数组及文件结构
node 前序节点选择 sourceNodeId；可选 path: "0.value" / "rows.0.金额"前序节点输出或其中字段，保留类型
dom 网页内容使用 Selector 工具、已有节点的 DOM 或手动填写 target；read 选择 text、value、attribute字符串，开启 multiple 返回字符串列表

source=node 的字段路径相对节点输出本身，而不是整个运行日志。未执行的前序节点、未定义变量、缺失字段、缺失 DOM / 属性均报失败，不伪造空值；合法的 0、false、null、空字符串和空数组正常返回。路径不能访问原型，也不支持 JavaScript 表达式或 eval。

DOM 输出只读，不激发页面事件。默认要求唯一匹配；读取列表需开启 multiple，最多 1000 项。read=attribute 必须填写 attributeName，例如 data-status、aria-valuenow、href；value 读取 input / textarea / select 的当前值，而不是 HTML 默认属性。支持 iframe 的 target.frameUrl 定位机制。拒绝读取密码、隐藏输入或脚本节点；普通页面内容仍可能包含业务敏感信息，请仅将其返回给已授权的 Agent。不会调用 AI 供应商。

MCP 返回#

run_page_workflow 直接返回以下字段；debug_page_node / debug_page_workflow 将它们放在 result 中。

json
{
  "ok": true,
  "output": "未成功",
  "outputs": { "未完成结果": "未成功" },
  "businessOk": false,
  "steps": []
}
  • ok：执行流程是否正常完成，或错误是否已由失败分支处理。它不等于取数、下载、发送等业务已经成功。
  • output：本次最后执行的 Output 值。
  • outputs：按 Output 节点名称汇总；循环中同一节点执行多次保留最后一次输出。
  • businessOk：outcome=success 标记 true，failure 标记 false；neutral 不作业务标记。任一 Output 标记 failure 时，以 false 为准，不被后续成功标记覆盖。

未执行 Output 时不附加上述输出字段。每次运行独立收集；不会读取历史手动参数或上次输出。后续步骤报错仍返回 ok=false，已产生的输出仅作为诊断，不应覆盖执行错误。Agent 应同时检查 ok、businessOk 和必要的步骤校验。

Output 按普通连线继续运行；不连接后续节点即结束当前路径，并非强制退出所有循环。需要立刻结束时应将其配置在分支末尾，且不要再连接有副作用的后续步骤。

“未取数完成”分支#

在检索第三列状态的 Query 上设置 onEmpty: "failure"。成功出口连接“下载”；失败出口连接：

json
{
  "id": "not_ready",
  "kind": "output",
  "name": "未完成结果",
  "source": "text",
  "value": "未成功",
  "outcome": "failure"
}

无匹配状态走失败出口，但匹配检查不修改页面。其他 Query 错误也走失败出口；Agent 可通过 steps[].diagnostic.code 区分 QUERY_NO_MATCH 和定位 / 配置异常。旧 Query 不设置 onEmpty 时仍走成功出口返回空列表，兼容已有流程。

“已触发下载”的 Output 只表示点击已执行，不保证文件下载完成；要判断完整文件落盘仍需核对浏览器下载状态或本机文件，不能把文字声明当作文件校验。

使用独立工具 delete_page_node，不需要替换整份 nodes 数组。先用 get_page_workflow 获取当前节点 ID 与 updatedAt，再传入：

json
{

返回保存后的完整工作流及新 updatedAt。支持循环/分页内部的真实节点 ID；删除节点会清理同一作用域内关联连线，删除容器也会移除内部所有节点。删除子流程入口会清除失效的 entryNodeId。不会自动重连前后节点，也不会执行网页操作。

开始节点、虚拟入口、缺失节点、错误密钥、版本冲突以及删除后残留的 Output / AI 等显式节点 ID 引用会拒绝，原图不变。先调整引用，或通过 edit_page_workflow 的 operations 在一次原子编辑中批量删除相关节点：

json
{
  "operations": [
    { "type": "remove_node", "nodeId": "dependent_output" },
    { "type": "remove_node", "nodeId": "wait1" }
  ]
}

批量编辑同样需要 instanceId、workflowId、key、expectedUpdatedAt。模板字符串中的节点名称引用仍需调用方同步调整。旧 remove_node 入口保留，但删除不存在节点会明确报错。新工具使用既有 edit_workflow 桥接协议，兼容已有支持工作流编辑的 broker；需重启 MCP 客户端以刷新工具列表，并重新加载新版扩展。

日期时间区间（插件 v0.10.51）#

Calendar 的 date、endDate 可引用 YYYY-MM-DD HH:mm:ss 文本参数。包含时间时使用独立 Fusion Next 日期时间区间适配，自动点击日期、时分秒选项和日历内部确定，最终同时核验主表单起止值，精确到秒。纯日期请求保留原路径，不改变原有配置。不支持的时间控件会失败，不会忽略时分秒。配置和安全边界见 日历日期时间说明。

异步类目筛选与跨页查找（插件 v0.10.50）#

自定义下拉输入应从页面快照读取 role=combobox 的控件，而非包含瞬时 next-focus 的外层路径。DOM 节点使用 event: {"type":"select","value":"{{filter_category}}","optionalValue":true,"minWaitMs":1000,"maxWaitMs":2000}：参数为空不打开下拉；非空时展开、随机等待，再等待异步选项出现，按名称完全匹配，最后核验已选标签。重复选项、超时或只有点击但未选中均失败。原生 select 的 value/标签选择保持兼容。

Query 的 candidateSelector:"tbody > tr" 配合 readSelector:":scope > td:nth-child(2)"，可只读取第二列进行比对，但返回完整行，供后续选择该行第一列 radio。normalizeWhitespace:true 去除首尾空白并合并连续空白，仍区分大小写、标点及内容；maxResults:1 只返回文档顺序中的首个匹配项。默认不限制返回项数。

分页容器配置 stopWhen:"{{本页精确匹配.output}}" 后，每页先执行完整内部流程，再检查引用结果：空列表继续翻页，非空结果正常完成。radio 勾选等子节点出错时不会提前报成功。此字段只接受变量引用，不执行代码；不存在的变量报错。maxPages 的安全上限支持 5000，触及上限而未到末页仍报失败；全局执行预算最多 50000 步，单图循环保护仍为 1000 步。

异步表格应在查询后和每页子流程开头添加 Watch，监听实际加载标志。例如 Fusion Next 的加载容器 class 在请求期间含 next-open，结束后移除，可用 ^(?!.*\\bnext-open\\b).*$ 正则等待结束。应先通过页面检查确认实际标志，不要把固定延时当成数据加载成功。

透明原生 radio/checkbox 可通过关联的可见 label 操作，最终验证的是 input 的 checked 属性，而不是 click 是否触发。流程可止于勾选，除非用户授权，不应添加抽屉确认或业务提交步骤。

页面截图（插件 v0.10.18 / MCP v0.10.0）#

capture_page_screenshot 使用相同的 instanceId、workflowId、key，返回 MCP 图片块和一段 JSON 元数据，不返回一大段图片 JSON，也不依赖 CDP。只截指定实例当前活动的 http/https 标签页，不会自动切换标签页。

模式：

  • mode: "viewport"：当前可视窗口。
  • mode: "region"：使用主文档唯一 selector，或者 region: {"x":100,"y":200,"width":600,"height":400}，二选一。矩形相对整个主文档左上角，单位为 CSS 像素，不是屏幕/设备像素；大区域可滚动拼接。iframe 在窗口中可见的内容也会被截图，但 selector 只在主文档查询。
  • mode: "fullPage"：按照截图开始时的文档尺寸横向/纵向滚动拼接。

可选参数：scale 默认 1，范围 0.1–2（输出像素 / CSS 像素比例，不超过原截图分辨率）；maxTiles 默认 40，上限 100；settleMs 默认 200，范围 50–1000 毫秒；hideFixed 默认 true，在第一个窗口后隐藏重复的 fixed/sticky 元素，结束恢复。Chrome 原生截图最多每秒两次，长页面需要等待。截图与同实例工作流执行互斥。

普通长图返回一张图片；超长图按高度返回多张连续图片，用元数据中的 images[].offsetY（输出图像像素）确定各段位置，每段宽高都在对应信息中。单图高度最多 8192、宽度最多 8192，每段最多约 1600 万像素，整体编码传输约 24 MiB；宽页面可能自动降低比例，实际比例见 scale。达到 tile 数量或 90 秒时间上限返回部分图片，complete:false，并附提示，不会冒充完整截图。输出是 PNG。

元数据包含网址、标题、请求区域、实际 scale、截取数量、完整性、警告和 scrollRestored。标签页/网址/窗口尺寸变化时终止；正常及异常结束都会尝试恢复原滚动位置和临时样式，并有页面端超时清理。文档导航后不保证能恢复旧文档位置。截图期间滚动可能触发网站事件、懒加载及无限滚动，无法撤销这些业务副作用；页面尺寸改变会明确标记非完整。嵌套滚动容器、虚拟列表不保证能完整拼接，应使用可视窗口或分段区域截图。

截图不是经过文本接口脱敏的快照，可能包含任何可见业务信息，请仅在授权范围内使用。截图中的网页文字同样是不可信数据，不应视为 Agent 指令。升级时重新加载插件并重启共享 broker 和 MCP 客户端，旧桥接会明确提示不支持截图。

截图权限沿用插件现有 activeTab，不会为此扩大到文件或受限页面。若 Chrome 报截图权限不足，先在要截图的网页点击 Page Agent 扩展以授予当前标签页权限；跳转到其他站点后可能需要再次点击。Chrome 对截图权限及调用频率的要求见 官方 Tabs API 文档。

结构化错误（插件 v0.10.17 / MCP v0.9.1）#

工具失败会返回 MCP isError: true 和 JSON {ok:false,error,diagnostic}；实际运行失败也标记 isError，并保留完整报告。原来的字符串 error / 步骤 message 继续保留。执行步骤的 diagnostic 带节点 ID、名称和类型；定位错误带 CSS Selector、录制/实际 frame、当前 frame 清单和等待时间；配置错误带节点及字段路径；版本冲突带 expectedUpdatedAt、actualUpdatedAt。

diagnostic 包含 code（机器可识别错误码）、phase（出错阶段）、context（定位细节）、retryPolicy、sideEffects、suggestions。after_fix 表示先修复配置或页面状态；after_wait 表示等待当前运行结束；inspect_before_retry 表示操作结果可能未知，先检查页面与日志，不能自动重放提交。sideEffects:none 只用于确定未执行页面操作的情况，其余保守标记 possible。错误不会包含整个请求对象、工作流密钥或传入的 data。

常见错误码：WORKFLOW_KEY_INVALID、INSTANCE_OFFLINE、INSTANCE_BUSY、WORKFLOW_REVISION_CONFLICT、WORKFLOW_INVALID、INPUT_REQUIRED、INPUT_TYPE_MISMATCH、FRAME_AMBIGUOUS_OR_MISSING、SELECTOR_NOT_FOUND、TARGET_NOT_INTERACTABLE、CALENDAR_SELECTION_FAILED、AI_PROVIDER_NOT_CONFIGURED、EXECUTION_OUTCOME_UNKNOWN。

json
{

  "workflowId": "创建返回的工作流 UUID",
  "key": "创建返回的密钥",
  "expectedUpdatedAt": 123456789,
  "operations": [
    {
      "type": "update_node",
      "nodeId": "start",
      "patch": {
        "inputs": [{"id": "p1", "name": "table_name", "type": "string", "required": true}]
      }
    },
    {
      "type": "add_node",
      "node": {
        "id": "input1",
        "name": "输入名称",
        "kind": "dom",
        "position": {"x": 360, "y": 100},
        "target": {"name": "输入名称", "selector": "#name", "frameId": 0, "tagName": "input", "label": "名称"},

      }
    },
    {
      "type": "connect",
      "edge": {"id": "e1", "sourceNodeId": "start", "targetNodeId": "input1", "sourcePort": "success"}
    }

}

实际的 expectedUpdatedAt 必须来自最近读取/编辑返回值。操作数组全部成功才保存，任一步无效不会保存部分修改。update_node.patch 是浅合并，修改 target、event、inputs 等嵌套属性时提供完整的新属性对象。节点 ID、名称、连线 ID 必须唯一；每个输出端口最多连接一个节点。删除节点会同时删除其关联连线；开始节点不能删除。

operations 支持 add_node、update_node、remove_node、connect、disconnect。disconnect 用 edgeId 指定连线；修改连线可在同一批次先断开再连接。也可直接传完整 nodes、edges 替换画布。成功/失败使用 success/failure；循环主体和结束使用 body/done。

完整调试传 data: {"table_name": "测试名称"}。单节点调试不自动执行开始节点或前置节点；需要前置输出时传 context，例如 {"查询列表": {"ok": true, "output": [{"selector": "#row1"}]}}。循环节点单独调试仅解析列表，不执行主体；完整遍历用完整流程调试。单节点的开始参数也按声明校验。

调试不是模拟预览：点击、输入、导航、提交均是真实操作，应在用户授权范围内使用。同实例的手动画布运行和 MCP 调试互斥。失败不会自动重复点击。断线/超时可能代表操作已发生，应先读取页面和日志确认再重试。报告含运行 ID、工作流版本、时间、逐节点结果与验证信息；日志写入失败不改变已完成的执行结果。

Agent 创建的工作流立即出现在插件列表中，可以继续用画布编辑。Agent 更新已有工作流不会替换用户未保存的编辑画布；该画布保存时会提示版本冲突，需重新打开最新定义。

通过路径上传文件（扩展 0.10.56 / MCP 0.10.14）#

上传使用现有网页节点 kind: "dom"，事件为 event: { "type": "upload", "value": "{{文件路径}}" }。Start 将同名参数声明为 string（单个路径/换行分隔）或 array（路径字符串数组）。target.selector 指向唯一的 input[type=file]、关联的 label 或含唯一文件框的容器；保存当前 frameUrl，不按可见性排除隐藏文件框。inspect_page_content 会返回文件框的 upload.accept 与 upload.multiple，不会返回 fakepath。

json
{
  "id": "upload_contract",
  "kind": "dom",
  "name": "上传合同",
  "target": {"name":"合同文件", "selector":"#contract-file", "frameId":0, "frameUrl":"https://example.com/contracts", "tagName":"input", "label":"合同文件", "attributes":{"type":"file"}},
  "event": {"type":"upload", "value":"{{文件路径}}"}
}

调用 run_page_workflow / debug_page_workflow 时，data 传 {"文件路径":["/Users/li/合同.pdf"]}。这些路径在运行 MCP 服务的本机解析，不在 Agent 远端解析。需要连接本机 MCP 0.10.14+ 共享桥接检查路径和文件元数据，Chrome 125+ 原生设置文件选择并从磁盘上传，不传 Base64 内容；绝对路径、最多 20 文件，不再设置 20 MB 大小上限，不支持文件夹或 URL。网站和浏览器自身限制仍适用。

输出只有文件名、大小、MIME 和修改时间，filesSelected=true / serverUploadVerified=false 表示文件已选入控件并触发页面事件。页面可能立即发起网络上传，请用后续 Watch/Query 确认业务成功。控件清空、导航或通信中断可能发生在上传已触发之后，禁止自动重试；先检查实际页面/服务端记录。AI 推理节点动态生成的事件不能读取本机文件，应使用显式配置路径的上传节点。

约束#

  • workflow.id 是工作流的全局唯一标识。新工作流使用 UUID v4。导入时如与本机已有 ID 冲突，插件会生成新 ID。
  • nodes 保存开始、网页操作、检索、输出、请求、智能分析、等待和循环等节点；edges 保存节点之间的成功、失败、遍历和完成路径。请求节点配置与返回值见 请求节点。
  • Start 节点的 targetUrl 是执行入口。录制生成的工作流会自动写入开始录制时的网页 URL。
  • 配置了 targetUrl 时，每次运行都会重新导航到该地址（即使当前地址相同），等待新的主文档导航与加载完成。URL 留空才复用当前页面。普通/强校验仅控制导航后最终地址的校验范围，不决定是否导航。Start 日志记录 previousUrl、requestedUrl、url 和 navigated；地址加载完成不代表业务控件已经可用，后续节点继续进行控件校验。
  • 网页节点的 target 保存 selector、元素类型和可读标签，event 保存点击、输入、选择、滚动、右键、长按等操作。
  • target.frameUrl 可选，保存节点所在文档的地址，用于 iframe 重建后的重新定位；frameId 仅是录制时的提示。旧工作流没有 frameUrl 时，会通过 selector 唯一匹配当前 frame；跨 frame 匹配不唯一时停止，避免误操作。
  • 网页操作的 selector 失效时，可用 target 已记录的元素类型、名称、placeholder 等稳定身份信息唯一定位；按钮可用已记录文本消除歧义。找不到或有多个匹配时走失败分支，不会猜测并点击第一个节点。Query 检索范围和多元素读取仍使用配置的 selector，不进行单节点身份恢复。
  • 执行前最多等待 10 秒进行只读定位检查，每次刷新当前 frame 列表，适应主页面加载完成后才创建的 iframe 或异步渲染的表单。目标操作仅发送一次；不会因等待或响应通道断开重复点击。超时错误包含当前 frame ID 和可连接脚本数量。
  • CSS selector 属于目标文档，不需要写入 iframe 路径或 XPath。后台枚举各级 frame，在各文档独立定位后向匹配文档执行；旧节点缺少 frame 信息或 frameId=0 时也允许唯一匹配子 frame。已保存 frameUrl 的节点保持文档范围，不会跳到其他 iframe。同名 selector 仍核验记录的元素类型和稳定属性；结果歧义时停止。操作失败会报告实际命中的 frame ID、文档 URL，区分“未找到”和“已找到但禁用”。
  • 访问密钥不属于工作流内容，永远不会写入导出文件。导入工作流后，本机为其生成新的访问密钥。
  • MCP 执行必须同时提供目标 Chrome 插件的 instanceId、workflowId 和对应密钥；参数数据放在 data JSON 对象中，按 Start 节点声明的同名字段映射。实例 ID 属于 Chrome 配置文件中的插件安装，不属于工作流导出文件；导入到另一实例后需要使用该实例的 ID。

机器可读约束见同目录的 workflow.schema.json。

Query 节点#

Query 只读取页面，不触发事件。target 与网页节点相同，指定范围 selector 和 frameId；query 配置范围内的候选元素与匹配规则：

json
{
  "id": "query_orders",
  "kind": "query",
  "name": "订单检索",
  "target": { "name": "订单检索", "selector": "#orders", "frameId": 0, "tagName": "div", "label": "订单列表" },
  "query": {
    "candidateSelector": "a",
    "includeRoot": false,
    "source": "attribute",
    "attributeName": "href",
    "match": "regex",
    "pattern": "^/orders/[0-9]+$",
    "regexFlags": "i"
  }
}
  • candidateSelector：CSS selector，空字符串或 * 检索所有后代；includeRoot 决定是否也检索范围元素本身。
  • source：attribute 按具体属性名读取（即 getAttribute，不是 JavaScript 属性）；value 读取表单控件的当前值，其他元素读取文本；text 读取 textContent。
  • match：exists 表示属性存在或不过滤值；equals 完全相同；contains 包含；regex 正则匹配。正则无需两侧斜杠，选项单独写在 regexFlags 中。属性不存在时不匹配，包括空字符串的正则。
  • 范围 selector、候选 selector、属性名和匹配内容支持 {{变量}}。
  • 输出为按文档顺序去重的 DOM 快照数组，每项有 selector、frameId、tagName、label、name、value、text、matchedValue 和完整 attributes。不是可跨进程传递的活 DOM 引用；后续操作使用 selector 重新定位。
  • 循环数组配置为 {{订单检索.output}}，循环内操作可用 {{item.selector}}、{{item.value}} 或 {{item.attributes.href}}。AI 节点的节点输入可直接选择 Query，MCP 执行结果的对应 step.data 返回同一数组。
  • 没有匹配项成功返回 []；范围不存在、非法 selector、缺少属性名或无效正则走失败出口。

上传文件事件#

网页节点支持 event.type="upload"，event.value 必须是非空路径配置或变量表达式（例如 {{文件路径}}）。精确变量引用可以解析为路径字符串数组；路径文本支持单行或换行分隔，也接受 JSON 字符串数组。目标可以是文件框、关联 label 或含唯一文件框的容器。Start 参数及导入导出保留此事件配置；不会将文件二进制写入工作流文件。实际上传依赖 Chrome 125+、扩展 0.10.56+、本机 MCP 0.10.14+；最多 20 个普通文件，不再设 20 MB 大小上限。MCP 仅预检并返回路径/元数据，Chrome 直接读取磁盘文件，内容不经过扩展消息；网站和浏览器自身限制仍适用。

v0.10.57 定位描述#

PageTarget 可携带 locator（version=1、selector、tagName、inputType、confidence、candidates）及 frameName。candidate 保存独立 CSS selector、可选 anchor，以及精确 match（text/value）；text 按空白归一化后完整相等，禁止 contains 猜测。优先级为 id、name、上层 ID 内精确身份、语义属性/文本、class、最终位置。多个候选不是拼接成一个位置路径；只在更高优先级规则没有匹配时回退，匹配多个元素立即失败。已有稳定祖先范围时，较弱全局规则不会跨出该范围。

录制、手动选择统一通过 describeElement 捕获。locator.selector 必须与当前 target.selector 一致才启用计划，显式修改 Selector 后按照用户 CSS 执行。Query/inspect 保留可独立执行的唯一 CSS，同时返回 locator 供调用方连同 target 保存，不能只保存看似非唯一的语义范围 CSS 而丢弃 match。

新捕获 frameQueryKeys 保留业务参数，排除 processId、sessionId、jsessionid、timestamp、_t、ts、、cachebust、cachebuster。URL 的 origin/path 和保留参数必须匹配，frameName 非空时还要匹配名称；新定位遍历所有候选 frame，frameId 只供诊断，不单独决定身份。旧节点未声明 frameQueryKeys 时保留完整 URL 精确匹配语义。

v0.10.58 已有节点自动修复#

执行节点前，先只读扫描当前目标文档。旧节点没有 locator、且 Selector 不含变量表达式时，可用已有 id/name、完整按钮文本、语义属性及旧 CSS 中的祖先 ID 恢复身份。原数字路径即使命中其他元素也不能作为身份证据；文本截断、重复身份、ID 被其他控件复用、祖先范围消失或多个 iframe 匹配时，不自动改写，也不发送该节点操作。通用非位置 CSS 检索范围（如 body、.rows）没有足够身份信息时保持原有检索语义。

修复发生在节点实际运行到对应页面时，支持嵌套子流程、Action、AI Selector 输入以及单节点调试。模板化 Selector 保持动态解析；现代 locator 和用户显式修改过的现代节点不被旧节点修复覆盖。重新枚举当前 frame，旧 frameId 不能用于消除歧义；保留业务查询参数，只排除已知运行参数。

新 target 保存 selectorUpgrade：version=1、previous（完整升级前 target）、upgradedAt、reason，同时写入新版 locator 和当前 frame 信息。RunResult.selectorUpgrades 列出升级/无法确认/并发冲突及是否已保存。升级后的目标按工作流/节点/AI 输入绑定定位，写入前比较最新目标与升级前快照；只修改该目标和 updatedAt，不覆盖并发修改的目标、连线、事件或其他节点。删除的工作流不会重建。只有通过唯一身份验证的节点会保存，即使后续步骤失败也保留已验证的升级。

升级结果会同步到当前编辑器；原 Selector 可在节点的“自动修复记录”查看，完整备份随工作流导出。下次运行直接使用保存的新规则。自动升级需要流程运行到对应页面，不会在离线状态猜测或遍历打开其他业务页面。

自动整理使用当前节点尺寸与现有连线，按从左到右的方向安排主画布和独立子流程，并将所有位置更新合并为一次编辑。子流程的虚拟入口保持固定位置。整理后自动适配视野，可一次撤销/重做；保存工作流会持久化新位置。

初始视野与缩放（0.10.62）#

进入编辑器后，等待节点文档与可见区域及引擎尺寸同步，再适配当前保存的节点位置。初始化不执行整理；隐藏后显示的画布会继续等待并初始化。正常编辑不会自动重设视野，拖拽或滚轮操作会中断待执行的初始适配。

悬浮工具栏的节点库图标用于新增节点，缩放区提供放大、缩小、百分比按钮（重置为 100%）和适应全部节点。缩放围绕当前视野中心进行，百分比随滚轮与工具按钮更新；视野操作不会成为工作流编辑或改变节点位置。

macOS 客户免安装包（推荐）#

分别提供 Page-Agent-<版本>-macOS-arm64.zip（Apple 芯片）和 Page-Agent-<版本>-macOS-x64.zip（Intel）。完整解压到固定且可写的目录，双击 Setup.command，即可使用内置 Node 生成本机 page-agent-mcp.json 并复制到剪贴板。在 MCP 客户端导入或粘贴配置，首次手动加载包内 extension 即可。

客户不需要安装 Node、npm、依赖或构建，也无需修改路径；不修改其他 MCP 客户端配置。目录移动后重新运行 Setup 并重新导入配置。包内保留运行时和启动脚本的执行权限。整体安装包尚未签名或公证；如被系统或企业安全策略阻止，应联系管理员审核，不要关闭保护或绕过系统警告。

维护者运行 npm run package:mac 一次生成两种芯片版本；也可指定 -- --arm64 或 -- --x64。打包时校验 Node 官方运行时 SHA-256，并只包含 MCP 的锁定生产依赖，保留第三方许可证。

Windows 客户免安装包（推荐）#

交付文件为 deliverables/Page-Agent-<版本>-Windows-x64.zip。完整解压到固定目录后：

  1. 双击 Setup.cmd：自动使用内置 Node 生成本机 page-agent-mcp.json，并复制配置到剪贴板。
  2. 在 MCP 客户端导入该 JSON 或粘贴配置，不用修改路径，不会自动覆盖其他 MCP 配置。
  3. 在 Chrome 扩展管理页开启开发者模式，加载解压目录内的 extension。

客户无需安装 Node、npm、依赖，也无需构建。包内不包含客户密钥或工作流，现有 Chrome 插件数据不受影响。移动解压目录后需再次双击 Setup，并重新导入配置。x64 包用于 Windows x64；ARM64 需由维护者执行 npm run package:windows -- --arm64 生成对应包。

维护者打包命令为 npm run package:windows，从 Node 官方站点下载固定版本运行时并验证 SHA-256，内置服务和依赖。程序不会修改防火墙、注册开机启动、自动授予权限或修改其他客户端配置。企业安全策略如阻止未签名脚本，应由客户管理员审核，不能绕过保护。

以下源码部署步骤仅供维护者或不使用免安装包的环境使用。

扩展不能启动本机 Node，也不能扫描本机文件系统。MCP 客户端通过 stdio 启动本机服务，服务再连接本机共享桥接。复制扩展 dist 不会同时安装 Node 或 MCP 服务。

在目标电脑准备#

安装 Node.js 22 LTS（或兼容的新版本），将完整项目放到目标电脑，例如 C:\Page Agent。在该目录打开终端运行：

text
npm --prefix mcp-server install
npm run mcp:build
npm run mcp:config

最后一条命令输出 JSON 配置，自动使用当前电脑的 Node 完整路径及项目脚本完整路径。将输出中的 JSON 添加到 MCP 客户端配置；不要复制 npm 的命令标题。Windows PowerShell 如拦截 npm.ps1，可用 npm.cmd 执行上述安装/构建命令；生成 JSON 中的 command 仍应是 node.exe。

示例（实际路径以命令输出为准）：

json
{
  "mcpServers": {
    "page-agent": {
      "command": "C:\\Program Files\\nodejs\\node.exe",
      "args": ["C:\\Page Agent\\mcp-server\\dist\\index.js"],
      "env": { "PAGE_AGENT_BRIDGE_PORT": "17373" }
    }
  }
}

参数数组会保留路径中的空格、中文。不要在路径字符串里再次嵌入引号，也不要将 command 改为 npm.cmd、npx.cmd 或带参数的命令行。

升级与排障#

  1. 重新加载 dist 插件，确认 v0.10.34 或更高；更新并重新构建 MCP 服务（本次为 v0.10.5）。
  2. 跨系统构建路径及从另一系统保存的路径会被清空，防止生成明显无法运行的配置。同系统迁移目录也需要重新运行 npm run mcp:config。
  3. 重启 MCP 客户端。插件“记住配置”不会自动修改其他客户端的配置。
  4. 若显示 Connection closed，先确认生成 JSON 中 command 和 args[0] 在本机存在，再查看客户端启动 stderr。仅 dist 扩展目录不够，需要保留 MCP 服务的 dist 和 node_modules。
  5. 如果客户端能列出工具但插件离线，检查本机 127.0.0.1:17373 的占用和安全软件。无需将端口开放到局域网，也不要关闭防火墙。
  6. 多客户端共用一个 broker；服务升级时需停止旧 broker 后重连客户端。不要为了排障结束所有 Node 进程，其他项目也可能依赖它们。

# 部署、运维与企业上线检查

> 历史评估资料：本篇保留 2026-10-10 的技术评估基线，未按 0.10.66 全量重审。当前安装、界面、节点与 MCP 使用请阅读 [最新使用手册](../README.md)。

基线：插件 0.10.18 / MCP Server 0.10.0。当前交付是 Chrome MV3 插件加本机 Node 服务，不需要 Page Agent 自建云端后台。

## 1. 部署组成与前提

| 组成 | 交付/要求 |
| --- | --- |
| 插件 | 项目根目录构建生成 dist；加载该目录 |
| MCP 服务 | mcp-server/dist/index.js 及 broker 等构建文件、对应运行依赖 |
| 浏览器 | 支持所用 Side Panel、MV3、storage.session、documentId 等 API 的 Chrome/兼容浏览器 |
| Node | 与当前依赖兼容的受支持版本；本次文档不声明未经测试的最低版本 |
| 目标网站 | HTTP(S)，授予必要扩展权限；业务账号可正常人工登录 |
| AI Provider | 仅 AI 节点需要；企业批准的 OpenAI-compatible 接口 |
| 本机端口 | 127.0.0.1:17373 可用，不对网络暴露 |

不保证所有 Chrome 版本和 Edge 环境均已实测。上线应记录准确浏览器、OS、Node 和部署方式。受限内置页、扩展商店页及无注入权限页面不可当作普通业务页。

## 2. 构建和安装

从项目根目录：

```bash
npm ci
npm run test
npm run build
npm --prefix mcp-server ci
npm run mcp:build
```

`npm ci` 使用锁文件，依赖下载本身需要企业批准的软件源和供应链策略。插件 build 包含 TypeScript 检查和 Vite 构建；MCP build 为 TypeScript 编译。

在 chrome://extensions 开启开发者模式，加载项目 dist。开发者模式安装适合试点；企业正式分发应按自身扩展管理/签名发布机制评估，当前仓库没有提供集中扩展政策管理服务。

加载后在目标业务页面点击扩展，核对顶部实际加载版本。仅复制文件到 dist 不会让现有 Chrome 自动加载新代码。

MCP 服务分发不能只复制 index.js：还需 broker、其他构建模块及运行依赖。可以通过完整项目目录提供，不应臆造当前未实现的独立二进制安装包。

## 3. MCP 配置和路径

点击插件顶部 MCP，复制面板给出的配置到可信客户端。构建时带入 Node 和 mcp-server/dist/index.js 的本机绝对路径，不是浏览器扫描文件系统。

迁移到其他机器、移动项目或更新 Node 安装位置后，应重新构建或修改面板保存的路径。已保存自定义配置优先于自动值。企业配置示例见 [API 文档](api-reference.md)。

`ws://127.0.0.1:17373/extension` 不是客户端 HTTP MCP 地址。插件不能自行启动 Node；MCP 客户端运行配置命令后自动连接或启动共享 broker。

当前插件固定 17373，Node 的 PAGE_AGENT_BRIDGE_PORT 单独改动会造成双方不一致。不要只改环境变量，也不要为了多客户端使用随意不同端口。

## 4. 多客户端和多实例

多个 MCP 客户端分别启动 stdio 进程，共享一个本机 broker。broker 作为 detached 进程运行，关闭一个客户端不会停止它。插件会自动重连，退避约 1–30 秒，心跳约 20 秒。

实例 ID 在配置文件内持久保存。同一个 Chrome profile 的不同窗口不是不同插件实例。不同 profile 独立安装插件可产生不同 ID；复制整个 profile 会复制 ID，连接时会被判重。应从独立 profile 初始化，而不是修改未知存储来绕过去重。

一个实例内运行、调试、截图互斥，查询可并发；不同实例独立。实例 ID 不能精确指定某个窗口/tabId，当前 MCP 入口主要面向该实例的活动页面，完整运行可通过 Start URL 导航。企业流程应使用专用 profile/窗口，避免人工与自动化同时操作。

## 5. 升级与版本管理

每次修改插件代码并发布，必须在构建前递增 patch，保持 manifest.json、根 package.json、package-lock.json root/package 版本一致。侧栏版本来自 `chrome.runtime.getManifest().version`，反映 Chrome 当前加载版本。

MCP Server 单独管理其 package/lock/version 和握手版本。文档变更本身不是插件代码发布，不应为了文档而伪造新插件版本。

升级步骤：

1. 导出已审阅工作流，记录当前版本、部署路径和安全配置。
2. 构建插件与 MCP，核对交付清单和产物摘要。
3. 在 Chrome 重新加载插件，核对顶部版本及页面权限。
4. 停用各客户端旧 MCP；若旧 detached broker 占端口，核实准确进程与路径后按运维流程停止。
5. 重新连接客户端，调用 page_agent_status/list_page_agent_instances 核对实例与版本。
6. 在测试账号回归关键流程，尤其 iframe、日历、提交和下载等路径。

不要强制杀掉所有 Node 或把端口错误当作可忽略。重连不自动重放中断操作；旧任务结果可能未知，应先查业务状态。

## 6. 备份、迁移与回退

标准 JSON 导出备份流程定义，不备份工作流 key、Provider API Key、手动历史和实例身份。它仍可能包含固定值中的秘密，备份需按业务数据保护。

新机器导入后获得新的本地 key，工作流 ID 冲突会换新；同步更新调用方配置。Provider 单独配置，MCP 路径单独验证。不要通过共享整个浏览器 profile 向多人分发密钥和登录态。

当前没有内置多版本工作流历史或数据库回滚。回退构建前应评估本地 schema 迁移与新节点的旧版本兼容性；不能保证降级版本可读取所有新格式。回退代码不撤销已经发生的业务操作。

## 7. 日志与排障

| 现象 | 检查路径 |
| --- | --- |
| MCP Connection closed | 准确命令/脚本路径、Node 能否启动、stderr；不要把 WS 当 HTTP MCP |
| 服务不支持多客户端/能力旧 | 检查旧 broker 和实际构建路径，升级后重新连接 |
| 实例离线 | 插件加载、连接面板、端口、实例列表；不切换其他实例尝试 |
| 页面没有动作 | Start URL、参数校验、当前实际版本、运行结果，不仅看总体提示 |
| Selector 找不到 | listFrames，读取当前文档，核对 frameUrl、隐藏副本和前置弹层 |
| 日历失败 | 弹层已打开、唯一可见容器、当前年月、目标日期、图标按钮变化 |
| 输入成功但业务失败 | 检查页面错误提示与后端业务结果，补流程后置读取 |
| 截图权限失败 | 在目标页面点击扩展授权，检查受限页面和跨站导航 |
| 截图部分完成 | complete/warnings、maxTiles、scale、页面动态变化和内部滚动 |
| 修订冲突 | 重新读取图，合并本地修改；不直接覆盖 |
| 运行超时/断开 | 结果可能已发生，先看页面和业务状态，禁止盲目重放 |

Node 输出诊断到 stderr，stdio stdout 用于 MCP；不要给 stdout 加普通启动打印。Chrome 扩展 Service Worker 控制台可辅助排障，但可能显示敏感业务信息，采集前应脱敏。

MCP 调试仅会话内每工作流最新报告，不是完整审计。客户端应记录 runId、流程修订、步骤状态、错误码和经脱敏的证据；避免把 key、明文参数、截图写进普通运维日志。

## 8. 性能与能力边界

当前没有经正式基准测量的 token 节省比例、吞吐量或 SLA。不使用 AI 节点可以减少插件模型调用，但不能由此计算外部 Agent 的全部成本。

结构校验限制约 500 节点、1000 连线；运行图有约 1000 步保护，Wait 实际最多 60 秒。大数组、巨大页面、复杂正则或录制过长需在试点中测量。

默认页面检查返回最多 100 节点，最大 200；截图默认 40 瓦片、可到 100，整页采集约 90 秒上限并有图像体积限制。长图不能保证包括所有虚拟/无限列表数据。

网络断开、业务系统变化、Chrome 更新、人工操作和权限变化都可能影响稳定性。业务功能测试不能代替安全测试，单元测试通过也不能证明真实第三方网页适配或无漏洞。

## 9. 企业上线检查清单

### 必须确认

- [ ] 记录插件/MCP/浏览器/Node 版本、Git 提交、锁文件与产物摘要。
- [ ] 目标系统账号为最小权限，使用专用受管 profile。
- [ ] 扩展站点访问仅覆盖必要业务，不加载非业务敏感网站。
- [ ] broker 只在 loopback，不向局域网、公网或不可信容器暴露。
- [ ] MCP 客户端和本机进程可信；理解并接受现有统一鉴权缺口。
- [ ] 对敏感生产任务，完成[安全文档 P0 控制](data-security.md)而非仅配置工作流 key。
- [ ] 插件 Provider 和外部 Agent 模型均通过数据处理审查。
- [ ] 检查参数历史、录制、定义、AI 输入、日志、导出、截图中的敏感信息。
- [ ] 提交、删除、审批等有业务层确认/幂等/审批，不只看 DOM 事件。
- [ ] 定义 key/API Key 泄露、页面结果未知和旧 broker 冲突的处理流程。

### 功能回归

- [ ] 未保存草稿不会被 MCP 读取或自动持久化。
- [ ] 手动历史不作为 MCP 缺失参数的默认值。
- [ ] Start 配置 URL 导航、普通/强校验和人工登录等待符合预期。
- [ ] iframe 重建后仍能定位当前唯一可见目标。
- [ ] 输入、下拉、勾选及 Enter 不重复提交，日历跨月/跨年自校验。
- [ ] 失败分支可恢复，循环有上限，日志能区分局部失败与整体恢复。
- [ ] 双客户端连接不互相顶替，同实例并发运行会拒绝。
- [ ] 并发编辑修订冲突不会覆盖，JSON 导入导出与新 key 验证通过。
- [ ] viewport/region/fullPage 截图权限、完整性和位置恢复通过实测。
- [ ] 超时、中断、日志存储失败不会诱发自动重复业务操作。

## 10. 交付建议

交付应包含插件 dist、完整 MCP 构建与依赖、企业文档、已审阅的示例流程（无真实密钥/业务数据）、版本清单及验收记录。当前仓库不提供集中管理控制台或企业后端，不应将这些未实现能力写入采购验收范围。

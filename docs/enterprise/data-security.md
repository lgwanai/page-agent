# 数据安全说明与企业风险评估

> 历史评估资料：本篇保留 2026-10-10 的技术评估基线，未按 0.10.66 全量重审。当前安装、界面、节点与 MCP 使用请阅读 [最新使用手册](../README.md)。

基线：插件 0.10.18、MCP Server 0.10.0。本文描述已核对的代码行为，并单独列出建议与缺口；不是渗透测试、合规认证或法律意见。

## 1. 安全结论

Page Agent 采取本机执行和本地保存的方式，常规确定性工作流不要求调用模型；指定工作流的运行和新编排工具具有 key 校验、明确实例路由、并发互斥和结果诊断等保护。

**当前版本仍以“受信任本机与受信任 MCP 客户端”为安全前提，不具备完整的企业级统一鉴权与数据治理。** 尤其是：

- WebSocket broker 没有调用方身份认证，loopback 不等于授权。
- 工作流 key 未覆盖旧 workspace/Action 和创建、导入等所有入口。
- API Key、工作流 key、手动输入历史没有应用层加密。
- AI 输入、页面快照、Query、截图、日志和导出不是统一的自动脱敏通道。
- 没有内置组织账号、RBAC、集中审计、业务审批或域名级操作策略。

因此，不能对客户承诺“全部数据不出本机”“所有接口均有 key”“只有批准的已有工作流可访问页面”或“达到某种安全认证”。受管终端、低风险试点与敏感生产部署应采用不同的审批标准。

## 2. 资产与信任边界

### 2.1 需要保护的资产

1. 目标网站中的客户、订单、财务、员工等业务数据。
2. 浏览器已有登录态及其代表的业务权限。
3. AI Provider API Key 和工作流访问 key。
4. 参数、录制内容、流程定义、运行日志和截图。
5. 工作流完整性：防止未经授权修改业务操作或目标 URL。
6. 执行正确性：防止操作错误页面、重复提交或把事件成功当成业务成功。

### 2.2 边界

| 边界 | 当前情况 | 企业需要控制 |
| --- | --- | --- |
| 操作系统 → 浏览器配置文件 | 本地用户/管理员可访问配置文件及进程 | 终端身份、磁盘保护、权限、恶意软件防护 |
| 本地进程 → broker | loopback WS；无统一客户端凭据 | 可信 MCP 客户端与本机进程，不公开端口 |
| broker → 插件 | role+实例 UUID 注册，无密码学远端身份验证 | 防止冒充服务/扩展，建议增加配对认证 |
| 插件 → 页面/iframe | Chrome 扩展权限与消息路由 | 限制网站权限，使用专用业务配置文件 |
| 插件 → AI Provider | 用户配置 HTTP(S) endpoint，Bearer key | 审批域名、强制 HTTPS、模型与数据策略 |
| 插件 → MCP 客户端 | 页面、图定义、日志、截图可返回 | 审查客户端模型、云端存储与日志策略 |
| 导出 JSON → 外部文件 | 流程可复制传播，无签名/加密 | 审阅、加密存储、版本与分发控制 |

## 3. 数据清单、存储与生命周期

### 3.1 本机存储

| 数据 | 存储位置/key | 内容与敏感性 | 生命周期 |
| --- | --- | --- | --- |
| 已保存工作流库 | Chrome local：pageAgentLibraryV2 | 节点、连线、URL、固定输入、AI 指令、旧 Action | 持久保存；非草稿 |
| 工作流访问 key | local：pageAgentWorkflowKeysV1 | UUID → 明文访问 key | 持久保存；有底层轮换函数，导入会换 key；没有有效期策略 |
| 插件实例 ID | local：pageAgentInstanceIdV1 | 配置文件实例 UUID | 重启不变；复制 profile 可能复制身份 |
| AI 配置 | local：pageAgentProviderV1 | endpoint、model、温度、Provider 名称 | 持久保存 |
| AI API Key | local：pageAgentProviderSecretV1 | 明文 apiKey | 持久保存，独立于流程库 |
| MCP 配置 | local：pageAgentMcpClientOptionsV1 | Node 与服务脚本的本机路径 | 持久保存，可能暴露用户名/目录结构 |
| 手动运行历史 | local：pageAgentRunInputs:{historyKey} | 参数名、类型、最后填入值 | 持久保存，无自动过期/敏感字段排除 |
| 录制进行中 | session：pageAgentRecordingSessionV1 | tabId、URL、事件、目标与普通输入 | 浏览器会话内；停止移除进行中记录 |
| 录制完成结果 | session：pageAgentRecordingCompleteV1 | 生成节点图及时间、网址 | 等待界面取走；新录制也会清理旧结果 |
| MCP 最近调试报告 | session：pageAgentDebug:{workflowId} | 参数输出、步骤数据、验收、AI 返回、错误 | 每工作流最新一份，非持久审计库 |
| 未保存画布与手动运行显示 | 编辑器内存 | 当前草稿、节点高亮和本次日志 | 当前 UI 会话，不写入工作流库 |

Chrome storage.local 不是网页 localStorage，但仍属于本机浏览器配置文件中的存储。当前代码没有用应用层加密或 OS Keychain 加密这些值。Chrome 的配置文件隔离和终端磁盘加密不能被表述为 Page Agent 自身的密钥加密。

storage.session 的设计是浏览器会话级暂存，可跨 Service Worker 重启；不是可靠持久备份，也不是安全删除证明。当前没有统一清理中心、保留期限策略、删除审计或密码学擦除。

### 3.2 浏览器登录态

插件不通过 `cookies` 权限枚举 Cookie，也没有把 Cookie 导出为工作流的设计。但是它在已经登录的页面执行操作，网站请求会使用该页面现有会话，因此插件和调用它的 Agent 可以使用当前用户的业务权限。

“不读取 Cookie”不能等同于“不能访问登录后的数据”。相同用户权限可能涵盖下载、提交、删除或审批，必须通过目标系统账号权限限制，而不是只依靠插件 key。

### 3.3 导出与导入

工作流导出不会自动附带单独保存的工作流 key、AI API Key、实例 ID 或手动输入历史。**但导出保留定义内容**，包括普通录制输入、固定值、URL 查询参数、属性、AI 指令；这些字段可能包含 token、个人信息或业务秘密。

导出前应人工或自动扫描秘密与个人信息，改为运行时参数，并使用企业批准的文件存储。当前导出没有应用层加密、签名或组织绑定，导入也没有发布方可信签名验证。导入文件不会立即执行，但不应因其是 JSON 就视为安全脚本。

## 4. 数据外发说明

### 4.1 无 AI 节点的常规运行

DOM、Query、Calendar、Wait、Loop 的执行由插件完成，不需插件发送模型请求。源码主要显式通信包括本机 WS 和配置的 Provider HTTP(S)；未发现自建云端工作流存储或专用遥测上传实现。

这不是“整个环境无外发”的结论：目标页面自身会访问业务服务器，外部 MCP 客户端可以把工具结果送给其模型、日志或云服务；构建依赖与目标网站另有各自供应链和隐私风险，未在本次文档中完成依赖审计。

### 4.2 AI Provider

AI 节点发送 instruction、具名 inputs、可用旧 Action 名称和系统提示；输入可以是文本、value、attributes、HTML 或前置节点结果。请求带 Bearer API Key，发往用户配置的 `{baseUrl}/chat/completions`。

Provider 测试也会发请求，但测试内容是简短连接测试，不是自动整页上传。模型返回 raw 内容可能进入步骤数据与会话调试报告。

当前配置没有统一强制 HTTPS 和企业 endpoint 白名单；错误或恶意 baseUrl 可接收 API Key 与数据。建议仅允许企业批准的 HTTPS 地址，必要时使用企业内网兼容模型网关，配合出口控制。设置为内网地址并不自动实现匿名化、零保留或合规。

### 4.3 MCP 返回

| 接口/功能 | 返回内容 | 数据安全注意 |
| --- | --- | --- |
| 状态、实例与列表 | ID、版本、名称、页面 URL/标题、时间 | 业务路径、URL 查询参数也可能敏感 |
| 工作流/旧 workspace | Selector、固定值、流程指令、旧 Action | 不返回独立 secret，但定义可能有秘密 |
| inspect_page_content | 控件文本、普通输入 value、有限属性、选项 | password/hidden 排除不是全面 DLP |
| Query 与 AI selector 读取 | 匹配文本、值、属性，某些读取可含 HTML | 不统一应用 inspect 的过滤 |
| 执行与调试 | Start 映射参数、步骤输出、验收 expected/actual、错误 | 日志可能复制输入或业务内容 |
| 截图 | 当前屏幕区域的 PNG | 没有打码，可能包括姓名、账号、报表、聊天等 |

插件不控制 MCP 客户端收到这些数据后的留存和模型训练策略。企业需审核两套 Provider：插件 AI Provider，以及外部 Agent 使用的模型服务。

### 4.4 截图特殊风险

截图没有 OCR 脱敏或密码区域自动遮盖。即使 inspect 排除了 password，页面上的可见敏感信息仍可能出现在图中。整个页面截图会覆盖远超最初可视窗口的数据，并可能因滚动触发网站懒加载/滚动处理器。

建议优先区域截图，只截排障必要范围；禁止把未脱敏截图发送到未批准的模型。MCP 调用日志和会话中也可能保留 base64 图片，不能仅清理插件日志就认为已清理所有副本。

## 5. 鉴权与密钥：已实现和缺口

### 5.1 工作流 key

key 使用 `crypto.getRandomValues` 生成 32 字节随机值，并编码为无 padding 的 URL-safe Base64；不是用户选择的弱密码。验证使用长度检查和逐字符异或比较，但不据此宣称整个调用过程具有经过验证的恒定时间保证。

新编排读取、编辑、校验、导出、页面读取、调试、截图及完整工作流执行会检查相应 key。用户可在插件列表复制 key；源码有底层轮换函数，UI 导入会调用它，但当前没有独立的“轮换密钥”按钮或 MCP 轮换工具。没有过期、组织身份、作用域、角色、调用预算、失败次数限制或集中吊销服务。

同一 key 同时可允许读取、修改、调试和运行该流程；尚未拆分只读、编辑和执行权限。运行结果返回到持有 key 的 MCP 客户端，key 不替代业务数据处理授权。

### 5.2 未统一鉴权的入口

| 入口 | 当前检查 | 风险 |
| --- | --- | --- |
| 实例发现/状态/列表 | 本机连接及实例路由 | 可枚举元信息和部分活动页面信息 |
| get_page_agent_workspace | instanceId，无工作流 key | 可读取完整已保存库，含固定值与指令 |
| list_page_actions | instanceId，无 key | 可读取旧 Action 完整定义 |
| run_page_action | instanceId，无 key | 有旧 Action 时可执行其业务动作 |
| create/import_page_workflow | instanceId，无额外创建凭据 | 可创建图并获得自己的 key，再读取页面或执行 |
| 插件内部 set_state handler | 实例检查；正常 broker 白名单不开放 | 若本机桥接服务不可信，不能依靠 broker 白名单作为全部防护 |

重要推论：即使没有旧 Action，客户端仍可通过新建工作流获得 key，再使用页面读取/截图等工具。**“工作流需要 key”不能限制一个已接入本机 broker 的不可信 Agent。** 对不可信客户端隐藏某个 MCP 工具只是客户端侧限制，不是服务端强制授权边界。

### 5.3 本机 WebSocket

broker 绑定 `127.0.0.1`，降低被局域网/公网直接访问的暴露面。`/mcp-client` 拒绝带 Origin 的浏览器连接，减少网页直接作为 relay 的风险，但任何本机非浏览器进程可以不带 Origin，当前没有额外凭据。

`/extension` 使用 hello role 和合法 UUID 注册身份，不验证扩展发布方证书或统一握手 secret，也没有完整 Origin allowlist。实例去重和回复 socket 绑定可以防串线，但不是密码学身份认证。还需关注恶意网页尝试连接该端点、恶意本机进程冒充扩展，以及旧服务停止后被其他进程抢占端口等威胁。

WS 是本机明文传输，未使用 TLS。不要通过 SSH 转发、代理、容器端口映射或修改 bind host 将其暴露给不可信网络。若将来提供远程服务，需要独立设计 TLS、客户端认证、授权、租户隔离和审计，不是改成 0.0.0.0 即可。

## 6. Chrome 权限与代码执行边界

当前权限为 sidePanel、storage、scripting、activeTab、tabs、webNavigation、debugger；host_permissions 和 content_scripts 覆盖全部 HTTP(S) 站点，all_frames，并支持部分 about:blank/源继承 frame。v0.10.38 新增 debugger 用于运行期间自动确认 alert；仅附加目标工作流标签页，执行结束后解除，不自动接受 confirm、prompt 或 beforeunload。该权限本身具有较广的调试能力，企业应按实际权限范围审核；运行时会出现 Chrome 调试提示，已有其他调试器占用时会明确报错，不抢占连接。

| 权限/机制 | 目的 | 风险/限制 |
| --- | --- | --- |
| tabs、webNavigation | 获取标签页、URL、frame 和导航 | 可以接触页面身份/路径等元信息 |
| scripting、广泛站点权限 | 注入/恢复脚本，操作 iframe | 敏感业务和非业务站点也在声明范围 |
| activeTab | 用户授予临时当前页操作/截图权限 | 截图仍受 Chrome 额外限制，导航后需重授 |
| storage | 流程与配置 | 本地存储会积累敏感参数与密钥 |
| all_frames | 操作各 iframe | 不能视为仅主页面数据访问 |

源码未声明 cookies、nativeMessaging 或 downloads 权限。但网页点击下载仍可能使用网站正常下载行为；没有这些权限不意味着没有业务副作用。debugger 已于 v0.10.38 声明，不应继续按旧版“无调试权限”评估。

扩展页面 CSP 的 script-src/object-src 为 self；connect-src 允许广泛 HTTP(S) 和固定本机 WS。没有 MCP 任意 JS 执行工具，JSON 模板也不是 eval。但 Content Script 仍有广泛页面读写能力，custom 事件和 AI invoke 可能触发业务处理器；“不是任意 JS”不等于“操作无风险”。

企业应尽量在专用 profile 中限制扩展站点访问。若为企业域名定制构建，需同时调整 manifest、脚本注入和相关功能并回归验证，不能仅宣称已有内置域名策略。

## 7. 提示注入与网页不可信输入

网页文字、属性、HTML、截图和模型返回都不能当作可信系统指令。MCP 工具描述有相关提醒，AI invoke 对 selector 输入名称和旧 Action 名称有存在性/绑定检查；这些控制仅减少无效引用，不能完整防止网页诱导模型执行危险动作。

例如，网页内容可能诱导外部 Agent 新建工作流、修改目标 URL、截图敏感区域或重复提交。当前没有独立的意图验证、组织策略引擎、操作批准机制或高风险按钮保护。

建议：

- 把网页内容作为带来源标签的数据，不允许覆盖用户任务和系统规则。
- 高风险业务由目标系统提供低权限账号、审批和幂等保护。
- 生产中优先已审阅的确定性流程，收紧创建/编辑/调试入口。
- AI 输入限于必要 DOM 范围，避免 html/attributes 整体读取。
- 企业敏感数据任务可以不使用 AI 节点，但还需限制外部 Agent 的数据外发。

## 8. 正确性、重复提交与可用性

已实现保护包括：明确实例路由、不自动回退；frame 当前文档探测；唯一可见目标要求；输入/选择/勾选结果比对；节点失败路径；同实例执行/截图互斥；编辑修订冲突；已派发动作后不自动重试；错误提示结果可能未知。

仍未实现服务器端事务、exactly-once、业务幂等键、自动回滚、持久化恢复、运行取消接口或用户操作隔离。网站和人工用户仍可能在运行中改变页面。点击事件成功不证明业务成功，日志丢失也不证明业务失败。

Agent 应先检查当前页面、业务状态和最近调试记录再重试。对支付、删除、提交等关键动作，应由目标系统提供幂等、确认和审计，不依赖插件消除全部重复风险。

资源保护包括节点/边数量、循环与执行步限制、页面读取上限和截图体积限制，但没有统一的业务运行配额、并发租户限流、所有 JSON 请求体的业务大小限制或完整防拒绝服务策略。复杂正则、巨大变量和录制事件量仍需控制。

## 9. 威胁场景与评估

| 场景 | 已有保护 | 剩余风险 | 建议 |
| --- | --- | --- | --- |
| 误操作其他 Chrome | 明确 instanceId、重复 ID 拒绝 | 同 profile 多窗口共享身份，活动页可能非预期 | 专用 profile/窗口，Start 明确 URL |
| 不可信本机 MCP 客户端 | loopback、部分工具 key | 可创建流程及旧接口旁路 | 服务端统一实例配对与调用方认证 |
| 本机恶意进程 | 无公网监听 | 存储读取、端口冒充、无凭据 relay | 终端防护、OS secret store、桥接双向认证 |
| AI 外发业务秘密 | 用户配置 Provider | endpoint/数据无限定，普通值未脱敏 | 受批网关、HTTPS、DLP、输入最小化 |
| 参数进入日志 | 会话内最新调试报告 | Start/expected/actual 可能含明文 | 敏感字段标识、日志脱敏与保留期 |
| 截图泄露 | 目标核对、区域模式 | 没有自动打码，客户端可持久保存 | 默认区域与审批、客户端留存限制 |
| 工作流被改 | expectedUpdatedAt 冲突保护 | key 同时有编辑权限，无签名审阅 | 读写权限拆分、发布签名/审核 |
| 导出流转 | 独立 key 不导出 | 固定值/URL/指令可能有秘密 | 扫描、参数化、加密分发 |
| 未知结果重复提交 | 不自动重放、诊断提示 | 外部 Agent/用户仍可再次运行 | 业务幂等与确认状态后重试 |

这些是基于源码的威胁分析，不是已验证漏洞利用或完整渗透测试结论。

## 10. 企业上线前建议补齐的控制

以下是建议，不表示当前已实现。

### 优先级 P0：敏感生产使用前

1. **统一桥接认证与配对**：MCP relay 与插件都验证可信 broker 身份，服务端验证调用方凭据；拦截不可信 Origin 和冒充连接。
2. **消除授权旁路**：新建/导入、旧 workspace/Action、内部写入与运行接口纳入统一实例级权限；不需要的兼容接口关闭。
3. **最小业务权限**：专用 Chrome profile、目标系统低权限账号，受控站点和 Provider 域名；高风险提交人工批准或目标系统审批。
4. **明确数据处理协议**：审核插件 Provider 与外部 Agent 双重数据链路，确定个人信息、截图和日志的接收方与保留策略。

### 优先级 P1：规模化部署前

1. OS 密钥服务/企业秘密管理，key 生命周期、吊销、读写/运行权限拆分。
2. 参数敏感标记；手动历史可关闭；AI、截图、日志、导出一致的脱敏策略。
3. 集中持久审计，记录主体、流程版本、目标站点、运行 ID、关键结果，禁止明文记录秘密。
4. 可信构建、锁文件依赖扫描、SBOM、产物摘要和经过审阅的发布流程。
5. 业务后置验收、幂等键和高风险动作审批；资源配额和明确运行取消机制。

### 优先级 P2：治理与体验

组织账号/RBAC、策略下发、工作流版本库和回滚、数据保留与清理界面、企业签名导入、可审计的远程服务设计、多租户隔离与运维仪表盘。

## 11. 安全事件处置

- 怀疑 key 泄露：停止相关 MCP 客户端调用，检查已发生业务动作，并由维护人员按受控流程更换底层 key；当前没有现成轮换按钮/工具，不能仅导入副本就认为旧工作流已被吊销。轮换也不取消正在运行的操作。
- 怀疑 API Key 泄露：在供应商侧撤销/轮换，检查额度与调用日志，清理本机配置和可能的客户端记录。
- 怀疑流程被篡改：停止执行，导出保存证据，核对版本与业务影响；不要直接运行可疑图来验证。
- 怀疑本机进程冒充：断开客户端和插件，按企业终端事件流程检查准确的进程/端口；不要无差别杀掉全部 Node。
- 页面结果未知：先确认业务状态；重跑前评估重复提交风险。
- 需要清理数据：分别处理工作流库、密钥、手动历史、会话报告、导出文件、MCP 客户端日志和模型端留存；当前没有“一键清除所有副本”的能力。

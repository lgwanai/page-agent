# 故障排查

先检查“版本、实例、当前页面、第一处失败节点”，再修改流程。不要把所有异常都归因于 Selector。

## 安装与连接

| 现象 | 检查与处理 |
| --- | --- |
| 更新后界面仍旧 | 查看扩展加载目录；重新加载使用原目录，不会自动切换到新包。核对侧栏实际版本并刷新网页 |
| MCP 显示未连接 | 客户端是否启动本机服务；Node 与脚本路径是否存在；不要把 WebSocket 地址当作客户端配置 |
| 路径仍指向旧包 | 重新运行本机 Setup、导入新配置，核对面板实际服务路径；共享桥接可能仍来自旧版本 |
| 有多个 Chrome 实例 | 用 `list_page_agent_instances` 核对实例 ID，不凭最近连接顺序猜测 |
| 显示正在执行 | 同一插件实例不能并发执行多个流程；确认已有任务或停止运行后再试 |
| 工作流找不到 | 核对 Chrome 配置文件、工作流 ID、回收站和导入后生成的新 ID |

## 定位、页面与 iframe

| 现象 | 检查与处理 |
| --- | --- |
| 控件未找到 | 页面是否已到达业务状态，前置弹层是否打开；检查当前 frame 与可见节点 |
| 多个元素匹配 | 缩小范围或补充稳定身份；不要任意选第一个元素 |
| iframe 编号变化 | 保存/检查 frame 文档 URL，重新枚举；业务 ID 变化不能通过忽略所有参数来处理 |
| 旧 Selector 修复失败 | 检查身份信息、重名、祖先范围与 URL 业务参数；歧义时不会自动猜测 |
| 日期或分页一直失败 | 选择完整弹层/分页容器，查看当前年月、页码与导航日志，而非仅观察是否点了箭头 |
| 点击成功但业务没完成 | 补充监控、检索或输出验证服务器结果在页面上的反馈 |

## 画布与运行

| 现象 | 检查与处理 |
| --- | --- |
| 节点太远或看不到全图 | 点击“适应全部节点”；100% 是实际尺寸，大图需要平移 |
| 点击节点没有设置面板 | 选中后点击下方“展开属性” |
| 快捷键没有撤销画布 | 焦点是否在输入框/对话框内；运行、保存或整理中会禁用画布快捷键 |
| 保存后运行结果不同 | 列表运行已保存版本；“运行画布”使用当前草稿 |
| 参数看起来为空 | 声明名、类型和 MCP `data` 字段是否一致；不要依赖另一份流程的手动参数记忆 |
| `ok:true` 但目标未完成 | 检查 `businessOk`、输出以及失败分支是否被正常处理 |

## 上传、请求、弹窗与模型

| 现象 | 检查与处理 |
| --- | --- |
| 上传路径不存在 | 路径属于运行本机 MCP 服务的电脑，不一定是模型所在电脑；使用真实绝对路径 |
| 文件已选中但未确认上传 | 查看网站上传回执；`filesSelected` 不等于 `serverUploadVerified` |
| 大文件仍失败 | 网站/浏览器限制、控件 accept/multiple、网络与服务版本；插件已取消旧 20 MB 限制 |
| 请求返回 JSON 错误 | 实际响应是否是 HTML、登录页或空响应；空响应选择 Text，HTTP 错误检查状态码 |
| 请求超时或断网 | 先检查服务器是否已处理写入；不要自动重发 |
| confirm/prompt 卡住 | 弹窗节点需同时监听并触发，不要前置另一个相同点击；区分原生弹窗与网页弹层 |
| AI 连接失败 | 检查本机 Provider、Base URL、模型/Endpoint、密钥和接口兼容性，先测试连接 |
| 邮件发送结果未知 | 检查发件记录和服务器状态；附件总大小、SMTP 配置与 MCP 版本也需核对 |

## 提交问题时提供什么

提供扩展/MCP 实际版本、失败节点名称和类型、错误码、当前页面/iframe 的脱敏地址、预期与实际结果，以及能复现的最小流程。截图中遮蔽访问密钥、令牌、个人信息；导出 JSON 中显式写入的请求头或正文需要另行检查。

不要提交整个 Chrome 配置文件或真实凭据。定位到结果未知的写入操作时，先确认业务状态，再重现问题。
